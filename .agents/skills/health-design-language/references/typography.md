# Typography · Locked stack

Paired against the ribbon heart: soft geometry, even weight, no sharp serifs.

Figma sample board: `Logo · HeartLine` → **HeartLine · Type Pairings** (`248:2`).

## Primary stack

| Role | Family | Weights | Notes |
|------|--------|---------|-------|
| **Display / CN UI** | **HarmonyOS Sans SC** | Bold / Medium / Regular | Brand-native; first choice for product + CN |
| EN lockup (soft) | Plus Jakarta Sans | Bold / SemiBold / Regular | Already Foundations Display |
| EN lockup (round) | SF Pro Rounded | Bold / Semibold / Regular | Closest to ribbon terminals; Splash / KV |
| Body / data / UI chrome | Atkinson Hyperlegible | Regular / Bold | Existing Foundations body — keep for metrics clarity |
| Illustration notes only | Caveat | Regular / Bold | Never in Tab / Button / Form |

## Pairing recipes

### A · Product default (recommended)

- Titles / CN: HarmonyOS Sans SC  
- Body / tabs / data: Atkinson Hyperlegible  
- Brand accent color on key numerals OK; type itself stays ink/white  

### B · English marketing lockup

- Mark + **Plus Jakarta Sans** or **SF Pro Rounded** wordmark  
- Tagline in Regular / Medium, shorter tracking than display  

### C · Avoid as brand voice

- Inter / Roboto / Arial as the *hero* identity face  
- Sharp transitional serifs, blackletter, script competing with the ribbon  
- Ultra-condensed or techno oblique as default  

## Optical rules with the mark

- Wordmark weight ≈ optical weight of the ribbon (usually Medium–Bold)  
- Don’t letterspace so wide that the lockup falls apart next to the continuous mark  
- Don’t set a headline that overpowers the brand mark on a branded first viewport  
- Chinese + Latin mixed lines: prefer HarmonyOS Sans SC for the whole line when possible  

## Foundations alignment

`Foundations · Type` historically listed Plus Jakarta (Display) + Atkinson (UI/Body).  

**Update under logo lock:**

1. HarmonyOS Sans SC becomes the **CN + primary product** face  
2. Plus Jakarta remains valid EN Display / lockup  
3. Atkinson remains Body / Data  
4. All new screens should document which recipe (A/B) they use
