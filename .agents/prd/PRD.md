# 运动健康 App 产品需求文档（PRD）

> **版本：** v0.1 · **阶段：** PRD → FigJam 流程 → 设计系统 → Lo-fi → Mid-fi  
> **平台：** iOS 手机优先（设计画板约 390×844）  
> **品牌：** 中性运动健康产品，无特定厂商品牌绑定

---

## 1. 产品愿景与目标 Product Vision & Goals

### 愿景
成为用户每天打开即可「看见自己、轻松动起来、安心连接设备」的运动健康伴侣——用清晰的信息与温和的鼓励，帮助用户建立可持续的日常习惯。

### 产品目标
| 目标 | 说明 |
|------|------|
| **每日回访** | 通过「今日」首页聚合当日状态与下一步建议，形成打开即有用的日循环 |
| **健康可理解** | 将复杂指标转化为趋势、区间与可行动提示，而非冷冰冰的数字墙 |
| **运动低门槛** | 从选运动到开练到总结，路径短、反馈及时、语气鼓励 |
| **设备可信连接** | 连接、同步、管理设备状态一目了然，减少「连上了吗？」的焦虑 |

### 设计交付约束
- 本阶段交付：**PRD → FigJam 用户流程 → 设计系统 → Lo-fi → Mid-fi**
- **不包含**高保真视觉稿、动效终稿、开发规格

### 语气原则
- 鼓励与清晰并重：用「还可以」「继续保持」「今天先走一小段」替代责备式文案
- 避免「未完成」「你失败了」「必须达成」等制造内疚的表达
- 数据呈现强调「趋势与下一步」，而非排名与惩罚

## 2. 目标用户与待办任务 Target Users & Jobs-to-be-Done

### 核心用户画像
| 用户类型 | 特征 | 核心诉求 |
|----------|------|----------|
| **日常健康关注者** | 25–45 岁，有手环/手表，关注睡眠、心率、步数 | 快速看懂今天状态，知道要不要调整作息或活动量 |
| **规律运动者** | 有固定运动习惯，跑步/骑行/力量等 | 开练快、记录准、练完有成就感与可回顾总结 |
| **设备新用户** | 刚买穿戴设备，对 App 与配对不熟悉 | 引导清晰、连接成功可感知、同步状态可信 |
| **轻度回归用户** | 曾用过类似 App，久未打开 | 冷启动不施压，先展示价值再逐步引导权限与目标 |

### Jobs-to-be-Done（JTBD）
1. **当我早上醒来**，我想一眼知道昨晚睡得怎样、今天活动建议是什么，以便安排一天节奏。
2. **当我想了解某项健康指标**，我想看到趋势、正常区间与简短解读，以便决定要不要改变习惯。
3. **当我想运动**，我想快速选类型并开始记录，练完后看到清晰总结与鼓励。
4. **当我买了新设备**，我想顺利配对并确认数据在同步，以便信任 App 作为数据中心。
5. **当我想回顾一段时间**，我想看到轻量洞察（周/月），而非被复杂报表淹没。

## 3. 信息架构 Information Architecture

### 底部导航（固定 4 Tab）
```
┌─────────┬─────────┬──────────┬─────────┐
│  Today  │ Health  │ Exercise │ Devices │
│  今日   │  健康   │   运动   │  设备   │
└─────────┴─────────┴──────────┴─────────┘
```

| Tab | 定位 | 一级内容模块 |
|-----|------|--------------|
| **Today · 今日** | 日循环中枢：状态总览 + 下一步 | 问候/日期、今日评分或状态摘要、活动/睡眠/恢复卡片、快捷开始运动、今日建议、轻量提醒入口 |
| **Health · 健康** | 指标目录与趋势 | 健康概览、分类指标列表（睡眠/心脏/活动/身体等）、单指标详情与历史 |
| **Exercise · 运动** | 开练与记录 | 运动类型选择、进行中会话、历史记录、单次运动总结 |
| **Devices · 设备** | 连接与管理 | 已连接设备列表、添加设备、设备详情、同步状态、基础设置 |

### 全局/二级结构（非 Tab）
| 区域 | 屏幕类型 | 说明 |
|------|----------|------|
| **Onboarding** | 冷启动、权限、目标设定 | 首次安装与久别回归 |
| **Insights** | 周/月轻量洞察 | 可从 Today 或 Health 入口进入，非独立 Tab |
| **Profile & Settings** | 账号、通知、单位、隐私 | 多 Tab 右上角头像/设置入口 |
| **Membership（轻量）** | 权益说明、订阅入口 | 非核心路径，可在设置或洞察中露出 |

### Tab 与二级屏关系示意
```
Today ──┬── Insights（周/月）
        ├── 开始运动 → Exercise 会话流
        └── 健康卡片 → Health 指标详情

Health ─┬── 指标详情 / 历史
        └── Insights

Exercise ┬── 运动选择
         ├── 进行中
         └── 总结 / 历史详情

Devices ─┬── 添加设备 / 配对
           └── 设备详情 / 固件与同步
```

## 4. 核心用户旅程 Core User Journeys

### 4.1 冷启动 Cold Start
| 步骤 | 用户行为 | 系统响应 | 设计要点 |
|------|----------|----------|----------|
| 1 | 安装后首次打开 | 欢迎页：价值主张（看懂健康、轻松运动、连接设备） | 1–2 屏，可跳过 |
| 2 | 登录/注册（可选延后） | 手机号或 Apple 登录；支持「稍后再说」 | 不阻断浏览 |
| 3 | 基础目标 | 轻量选择：更关注睡眠/活动/运动/全面 | 无「必须达标」话术 |
| 4 | 权限引导 | 健康数据、通知、蓝牙（设备相关）分步请求 | 每步说明用途与收益 |
| 5 | 设备引导（可选） | 「现在连接」或「稍后在设备页连接」 | 不强制 |
| 6 | 进入 Today 首页 | 展示已有数据或示例骨架 + 引导完成第一步 | 空状态友好、有 CTA |

**成功标准：** 用户 3 分钟内进入 Today 且理解 4 Tab 分工。

---

### 4.2 每日 Today 循环 Daily Today Loop
| 步骤 | 用户行为 | 系统响应 |
|------|----------|----------|
| 1 | 早晨打开 App，默认 Today Tab | 问候语 + 日期；今日状态摘要（睡眠、活动、恢复等） |
| 2 | 浏览卡片 | 可横滑或纵向卡片：昨晚睡眠、今日步数/活动、心率/恢复提示 |
| 3 | 点击感兴趣卡片 | 跳转 Health 对应指标详情，或就地展开简要说明 |
| 4 | 接受建议 | 「今天可以散步 15 分钟」→ 一键开始 Exercise 或标记完成 |
| 5 | 晚间回访 | 今日回顾小结：完成度、鼓励语、明日轻提示 |

**成功标准：** 用户无需切换 Tab 即可掌握当日状态并执行一个下一步动作。

---

### 4.3 健康指标下钻 Health Metric Drill-down
| 步骤 | 用户行为 | 系统响应 |
|------|----------|----------|
| 1 | 进入 Health Tab | 分类列表 + 置顶关键指标（睡眠、静息心率、活动量等） |
| 2 | 选择指标 | 进入详情：当前值、7 天/30 天趋势图、参考区间 |
| 3 | 阅读解读 | 1–3 句白话解释 + 「这意味着什么」 |
| 4 | 查看历史 | 日历或列表选日；支持周/月切换 |
| 5 | （可选）关联洞察 | 链至 Insights 查看更长周期模式 |

**成功标准：** 非专业用户能在 30 秒内理解指标好坏与趋势方向。

---

### 4.4 开始运动 + 总结 Start Exercise Session & Summary
| 步骤 | 用户行为 | 系统响应 |
|------|----------|----------|
| 1 | 从 Exercise Tab 或 Today 快捷入口 | 运动类型网格/列表（跑步、步行、骑行、自由训练等） |
| 2 | 选择运动 | 预置目标（距离/时长/卡路里/自由）与设备确认 |
| 3 | 开始会话 | 全屏或沉浸进行中 UI：时长、距离、心率区间、暂停/结束 |
| 4 | 结束运动 | 自动或手动结束；短暂加载后进入总结页 |
| 5 | 查看总结 | 核心数据、路线简图（若适用）、个人纪录提示、鼓励文案、分享/保存 |
| 6 | 回顾历史 | Exercise 历史列表 → 单次详情 |

**成功标准：** 从点击运动类型到开始记录 ≤ 3 次点击；总结页 5 秒内可读懂。

---

### 4.5 设备连接与管理 Devices Connect & Manage
| 步骤 | 用户行为 | 系统响应 |
|------|----------|----------|
| 1 | 进入 Devices Tab | 已连接设备卡片列表；无设备时空状态 + 「添加设备」 |
| 2 | 添加设备 | 蓝牙扫描列表 / 型号选择 → 配对引导 |
| 3 | 配对中 | 步骤指示、动画或图示、失败重试与帮助 |
| 4 | 配对成功 | 确认页：设备名、电量、最近同步时间 |
| 5 | 设备详情 | 重命名、取消配对、固件更新（若有）、数据同步开关 |
| 6 | 日常查看 | 列表展示连接状态、电量、上次同步；异常时温和提示 |

**成功标准：** 新用户首次配对成功率可追踪；同步状态一眼可见。

---

### 4.6 轻量洞察 / 会员（可选）Insights & Membership
**Insights：** 周/月聚合（睡眠规律、活动达标天数、运动总时长）；语气总结而非打分批判。  
**Membership：** 仅保留权益说明、订阅 CTA、恢复购买；不阻断免费核心功能。

## 5. 功能需求（按 Tab）Feature Requirements

### 5.1 Today · 今日
| 优先级 | 功能 |
|--------|------|
| **Must** | 今日状态摘要（睡眠、活动、恢复至少 2 项）；日期与问候；卡片跳转 Health/Exercise；下拉刷新 |
| **Must** | 空状态与数据加载骨架；快捷「开始运动」入口 |
| **Should** | 今日建议/下一步 CTA；今日完成度轻量可视化（环/条，非惩罚色） |
| **Should** | 晚间回顾小结；Insights 入口 |
| **Later** | 可定制卡片顺序；天气/日程关联 |

### 5.2 Health · 健康
| 优先级 | 功能 |
|--------|------|
| **Must** | 指标分类列表；至少覆盖睡眠、心率、步数/活动、卡路里 |
| **Must** | 单指标详情：当前值、趋势图（7 天）、参考区间、简短解读 |
| **Must** | 历史日选择/周月切换 |
| **Should** | 指标置顶/常用；多指标对比（同屏 2 项） |
| **Should** | 异常值温和提示（非警报式） |
| **Later** | 健康报告导出；第三方健康 App 数据合并说明 |

### 5.3 Exercise · 运动
| 优先级 | 功能 |
|--------|------|
| **Must** | 运动类型选择；开始/暂停/结束会话 |
| **Must** | 进行中核心数据（时长 + 距离或卡路里 + 实时心率若可用） |
| **Must** | 运动后总结页；历史记录列表与单次详情 |
| **Should** | 预设目标；个人最佳提示；GPS 路线简图 |
| **Should** | 从 Today/Health 一键开练并带回类型上下文 |
| **Later** | 训练计划/课程；社交分享卡片模板 |

### 5.4 Devices · 设备
| 优先级 | 功能 |
|--------|------|
| **Must** | 已连接设备列表（名称、连接状态、电量、上次同步） |
| **Must** | 添加设备流程（扫描/选择 → 配对 → 成功确认） |
| **Must** | 设备详情：取消配对、重命名 |
| **Should** | 配对失败帮助；手动同步按钮 |
| **Should** | 固件更新入口（若平台支持） |
| **Later** | 多设备数据合并策略 UI；家庭共享设备 |

### 5.5 全局 Global
| 优先级 | 功能 |
|--------|------|
| **Must** | 4 Tab 底部导航；统一顶栏（标题、设置/头像）；加载/错误/空状态组件 |
| **Must** | Onboarding（欢迎、权限、可选目标）；基础设置（通知、单位、隐私摘要） |
| **Should** | Insights 周/月页；账号登录与数据云同步说明 |
| **Later** | Membership 订阅；小组件与锁屏（仅记录需求，不在本阶段设计） |

## 7. 非目标 Non-Goals

| 非目标 | 说明 |
|--------|------|
| **高保真视觉** | 本阶段止于 Mid-fi，不含终版视觉、插画风格定稿、品牌 VI |
| **Web / 桌面端** | 不做响应式 Web 或桌面为主界面 |
| **平板优先** | 不针对 iPad 横屏或分栏布局优化 |
| **Android 专属** | 可预留扩展，但设计与组件以 iOS 手机为先 |
| **社交广场/UGC** | 不做社区信息流、排行榜羞辱机制 |
| **医疗诊断** | 不提供疾病诊断、处方或替代医生建议的表述 |
| **完整电商** | 不做设备商城全流程（可外链或 Later） |

## 8. 成功指标 Success Metrics

| 指标 | 定义 | 初期参考方向 |
|------|------|--------------|
| **D1 留存** | 安装后第 2 天仍打开 | 追踪基线 |
| **Today 到达率** | 会话中浏览 Today 首页的比例 | ≥ 70% 会话 |
| **开练转化率** | 进入运动选择并完成一次会话 | 追踪漏斗 |
| **设备配对成功率** | 开始配对流程中成功连接占比 | ≥ 85% |
| **权限完成率** | 完成核心健康权限引导的用户占比 | 追踪优化 |
| **指标详情 engagement** | Health 详情页人均停留与返回率 | 验证可读性 |

## 9. 开放问题 Open Questions

1. **登录策略：** 是否允许完全游客模式仅本地查看，还是部分功能必须登录？
2. **数据优先级：** 手机传感器 vs 穿戴设备数据冲突时，默认以哪端为准？
3. **运动类型 MVP：** 首发必须支持哪几种运动（建议：步行、跑步、骑行、自由训练）？
4. **Insights 深度：** 周洞察是否纳入 Must，还是 Should？
5. **会员边界：** 免费版与会员版功能切分是否需要在本阶段 FigJam 中体现？
6. **通知策略：** 默认开启哪些提醒，如何避免「通知疲劳」？
7. **地区与合规：** 健康数据存储地区、隐私文案是否需要分区域模板？
8. **离线能力：** 运动中无网络时，会话数据本地缓存策略是否需在 Mid-fi 标注？

## 10. 附录：设计协作顺序

```
PRD（本文档）
    ↓
FigJam：核心旅程泳道图 + 4 Tab 站点地图
    ↓
Design System：颜色、字体、间距、基础组件（Button 等）
    ↓
Lo-fi：线框，覆盖 Must 屏幕
    ↓
Mid-fi：灰度模块化，验证信息密度与导航
    ↓
（下一阶段）Hi-fi / 开发交付
```

**画板：** iOS 手机 390×844（@3x 思维），安全区与底部 Tab 高度需在组件库统一。
