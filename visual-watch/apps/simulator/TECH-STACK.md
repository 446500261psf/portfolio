## 1. 技术栈总览

| 层 | 选型 | 用途 |
|----|------|------|
| 构建 | Vite 8 + TypeScript | 开发服务器、打包 |
| UI 框架 | React 19 | 组件与状态管理 |
| 3D 渲染 | Three.js + @react-three/fiber | WebGL 场景（声明式） |
| 3D 工具 | @react-three/drei | OrbitControls / Bounds / 相机等封装 |

| 持久化 | localStorage | 记住上次调整的参数 |

无后端，纯静态前端应用。

## 2. 各模块实现方案

### 2.1 外形工作室（2D 三视图）

- **超椭圆方程** `|x/a|ⁿ + |y/b|ⁿ = 1` 定义表壳正面轮廓，n 由滑杆控制（2≈椭圆，4–5≈圆角方）
- SVG path 由参数方程采样生成；轮廓与尺寸线共用同一 `SCALE=5.5`，保证对齐
- 参数单位：场景 1 单位 = 1mm

### 2.2 3D 白膜 / 镜面玻璃

- **几何**：`createWatchCaseGeometry` 隐式挤出 —— 正面超椭圆沿 ±Z 各挤出半球形穹顶；
  上下半球**共享单一赤道环**（消除侧面中线接缝），极点用单顶点扇面封口
- **玻璃材质**：`meshPhysicalMaterial`，`#050505`、`transmission≈0.22`、`clearcoat=1`
- **反射环境**：`ReflectionStudioEnv` —— 两块可调 emissive 柔光板（位置/大小/强度/色温）
  经 PMREM 烘焙成环境贴图，驱动 `envMapIntensity`；反射是**大面积可控光带**而非点光源
- **相机**：`PerspectiveCamera` + OrbitControls；首次进入由 `Bounds fit` 自动取景，
  之后恢复持久化的方位角/俯仰角/距离

### 2.3 正视预览（镜面玻璃 Pool · UI 直接演示在玻璃上）

**产品定义**：玻璃同时具有**镜面反射**与 **UI 演示**两种效果——UI 不在
玻璃内部深处，而是直接浮现在镜面玻璃表面上（如手机屏）；侧缘保留
微弱的光带环绕（Pool 余韵）。

数据流：

```
Figma 表盘页（sZDBW36idsJ7op8FVhYq6W）
  → MCP 逐状态导出关键帧 PNG（972×972）
  → 白底泛洪转 alpha（构建期一次性处理）
  → public/dial/*.png
  → THREE.TextureLoader（sRGB 硬件解码为线性）
  → Pool 发光壳层（与玻璃共面的自定义 ShaderMaterial）
  → 加法混合叠加在镜面玻璃着色之上
```

- **双 mesh 同面叠加**：
  - **镜面玻璃壳**：`meshPhysicalMaterial`（原镜面参数：roughness 0.06、
    transmission 0.22、thickness c×1.2、clearcoat 1），柔光板 PMREM 反射
  - **Pool 发光壳层**：同一挤出曲面微放大 1.003 避免 z-fight，
    `AdditiveBlending` —— 反射 + 自发光在同一表面叠加
- **UI 显示层**：`frontness^1.25` 只作用于正面半球，按表面点 xy 采样
  Figma 光场 —— UI 稳定、清晰、无噪声
- **侧缘环绕**：赤道带（`sideness`）按 swirl 摆动采样光场 ×0.22 ——
  光带沿边缘缓慢流动，但不透视内部（保持镜面质感）
- **动画 uniform 化**：关键帧 morph（余弦往返）、呼吸 envelope（4–7bpm）、
  900ms 状态渡越全部 uniform 驱动，新旧状态 ×各两帧（4 sampler）单 pass 混合
- **场景结构**：镜面玻璃壳 + Pool 发光壳层 + OrbitControls 拖拽旋转
  （光源与 3D 白膜页共享）

### 2.4 参数持久化

- `localStorage` key `cove-simulator-state-v1`，120ms 防抖写入
- 记住：标签页、外形滑杆、3D 光源、表盘状态、材质、3D 相机角度与 Orbit 缩放
- 读取时逐字段校验 + clamp，坏数据自动回退默认值

## 3. 演进日志（技术变更 ↔ 效果变化）

> 倒序排列。每条记录：**改了什么技术 → 效果为什么变好/变坏**。

### 2026-07-11 · 镜面玻璃 Pool：透视内腔 → UI 直接演示在镜面玻璃上

- **变更**：
  1. 删除体积 raymarch（30 步循环整体移除），Pool 改为与玻璃共面的
     **发光壳层**：同一挤出曲面微放大 1.003，加法混合叠在玻璃着色之上
  2. 玻璃恢复原镜面参数（thickness c×0.3 → c×1.2 等），不再为「看见内部」
     而弱化玻璃
  3. 侧缘环绕光带：赤道带按 swirl 摆动采样光场 ×0.22，保留 Pool 余韵
- **效果变化**：✅ 玻璃质感回归 —— 正面同时呈现环境反射与 UI（加法混合
  天然叠加，黑色区域只剩反射、光带区域反射+发光）；侧/背视角是纯粹的
  镜面鹅软石，边缘有一圈微弱的光带环绕流动
- **为什么变好**：前一版为了「透视内腔的体积光」牺牲了玻璃的镜面感——
  体积雾要求视线穿透表面，视觉上玻璃就「变透明」了。产品定义其实是
  **表面复合**：镜面反射与 UI 演示同时发生在玻璃表面（AMOLED 贴合屏的
  物理事实也是如此），加法混合在同一曲面上叠两层材质即可，还省掉了
  每帧 30 步的 raymarch 开销
- **教训**：视觉目标要先分清「体积效果」还是「表面效果」，选错渲染
  模型会连带牺牲其他质感

### 2026-07-11 · 光场贴玻璃：纯体积雾 → 解析显示层 + 体积流动层

- **变更**：
  1. Pool 拆成双层：正面 UI 改为在光线入射内壁点**解析采样**（单次纹理
     采样，不参与 raymarch），体积层只负责边缘/背部流动与稀薄填充
  2. 体积密度的纵深偏置反转：原「光住潭底、正面变淡」→「前壁显示层
     最亮、背部次之」；填充密度 0.20→0.07
  3. 玻璃减薄：`thickness` c×1.2→c×0.3，Pool 内腔 0.965→0.985 贴近玻璃
- **效果变化**：✅ 玻璃厚重感消失 —— UI 像手机屏一样浮在玻璃表面正下方，
  清晰锐利（解析层无步进噪声颗粒）；侧/背视角仍保留 Pool 的边缘流动
- **为什么变好**：正面观感的关键不是「体积感」而是「贴附感」——
  手机屏之所以像 UI 浮在表面，是因为发光层距玻璃外表面 <1mm；
  纯体积雾把能量分散在整个纵深里，视觉上等于「隔了厚玻璃看投影」。
  解析层把能量集中在入射面一次性给出，既贴又亮还省 6 步采样
- **顺带修复**：uv clamp 在超椭圆角落外产生拉丝 → 越界处直接返回 0

### 2026-07-11 · Pool 体积光场：平面屏幕 → 体积 raymarching

- **变更**：删除嵌入玻璃下的平面显示屏（`createDialFaceGeometry` +
  `DialFaceAnimated`），新增 `PoolVolume` —— 自定义 ShaderMaterial 在超椭球
  内腔做 36 步光线步进，发光密度贴内壁 + 稀薄填充 + 潭底纵深偏置
- **效果变化**：✅ 符合产品定义 —— 整个玻璃内腔是演示场（Pool）：
  光沿背部与边缘流动，侧视/背视能看到光场充满内腔，而不是一块发光平板；
  Figma 关键帧仍决定光场的 xy 分布，morph / 呼吸 / 渡越动画全部保留
- **中途问题与修复**：首版出现同心带状伪影（步进量化误差在等值面上共振），
  用屏幕空间 hash 抖动步进起点把带状换成噪声；侧/背视角光路长导致过曝，
  加 Reinhard 式软压缩解决
- **关键技术点**：表壳挤出面恰好是超椭球 ρ=1 等值面，内外判定只需一次
  幂和计算，raymarch 成本极低；新旧状态 ×各两帧共 4 个 sampler 在单次
  raymarch 内完成全部混合，无需多 pass

### 2026-07-11 · 正视预览升级：2D 正交平贴 → 3D 玻璃实机演示

- **变更**：
  1. 正交相机 → 透视相机 + OrbitControls，可拖拽旋转观察
  2. 表盘面从「浮在壳体上方的平面」→「嵌入玻璃穹顶之下的 3D 显示屏」，
     嵌入深度 `dialScreenZ` 由挤出剖面方程反解，任意 n 值不穿模
  3. 屏幕材质 `NormalBlending` → `AdditiveBlending + premultipliedAlpha`
  4. 外壳从哑光黑 → 镜面玻璃（复用 3D 白膜页的柔光板 PMREM 反射与 lights 状态）
- **效果变化**：✅ 从「平面贴图对照稿」变成「实机演示」——正面看是玻璃反射
  叠加光场 UI（黑色区域保留玻璃高光，光带透出玻璃，像真的屏下 AMOLED）；
  旋转侧看能看到屏幕嵌在玻璃壳体内部
- **关键技术点**：加法混合天然适合自发光屏幕——黑像素加零光、亮像素加光，
  无需处理「屏幕遮挡玻璃反射」的层序问题；`premultipliedAlpha` 消除了
  位图透明角落的白色 RGB 溢出；玻璃 `depthWrite=false` 让内嵌屏幕可见

### 2026-07-11 · 正视预览重做：手绘 Canvas → Figma 关键帧位图

- **变更**：弃用 Canvas 2D 渐变手绘近似（`renderFigmaDial.ts`），改为直接加载 Figma
  逐状态导出的关键帧 PNG，`meshBasicMaterial` 多层叠加做交叉淡化
- **效果变化**：✅ 大幅变好。光带位置、颜色（Lift 琥珀 / Low 青绿 / Grounded 冷白）、
  边缘羽化与设计稿完全一致——手绘近似永远追不上设计稿本身
- **顺带修复的三个 bug**（非技术栈原因，是实现错误）：
  1. 正交相机 zoom 写死 → 改为随画布尺寸计算（之前表盘溢出只显示一角）
  2. 表盘面 z=0.999c 低于穹顶极点 z=c → 抬高到 1.02c（之前中心冒白斑）
  3. UV v 轴翻转 → Low 的底部光带曾跑到顶部

### 2026-07-11 · Orbit 相机持久化：Bounds 自动取景 → 球坐标恢复

- **变更**：`OrbitControls` 的方位角/俯仰角/距离存入 localStorage；
  有记录时跳过 `Bounds fit`（`fit={false}`），直接还原视角
- **效果变化**：✅ 刷新后视角不再跳回默认；首次进入仍自动取景，两者兼得

### 2026-07-11 · 参数持久化：内存 state → localStorage

- **变更**：新增 `simulatorStorage.ts` + `usePersistSimulator` 防抖 hook
- **效果变化**：✅ 每次进入不用从头调参

### 2026-07-10 · 反射方案：SpotLight/场景贴图 → emissive 柔光板 + PMREM

- **变更**：镜面反射先后试过 HDR 场景贴图（有杂景）、SpotLight（只有两个高光点），
  最终改为两块 emissive 平面烘焙 PMREM 环境贴图
- **效果变化**：✅ 反射变成**大面积可控光带**，位置/大小/强度/色温全部可调；
  场景贴图方案的杂乱反射消失；SpotLight 方案「两个点」的问题消失

### 2026-07-10 · 3D 几何：参数化半球拼接 → 共享赤道隐式挤出

- **变更**：上下半球原本各自生成顶点再拼接，改为共享单一赤道环的单网格；
  同时修复 `cosN(nu)` 误传弧度导致的破面
- **效果变化**：✅ 侧面中线接缝消失、V 形破面三角消失；法线连续，高光平滑

## 4. 已知取舍

| 决策 | 取舍 |
|------|------|
| 关键帧位图 vs 实时粒子场 | 位图保真度高、成本低；但无法做粒子级动态。PRD 的 cove-field 粒子引擎留给「潭面场」标签页 |
| PNG 白底泛洪转 alpha | Figma 导出的 PNG 背景是不透明白色；构建期一次性处理，运行时零开销 |
| 表面壳层 vs 体积 raymarch | 体积雾透视内腔会牺牲镜面质感（玻璃「变透明」）；产品定义是表面复合（镜面+UI 同面），共面壳层加法混合即可，且零 raymarch 开销 |
| 加法混合 vs transmission 透射 | transmission 渲染内部物体依赖折射通道，暗色玻璃下几乎不可见；加法混合直接把 UI 光叠加在玻璃着色之上，效果直观且省一次透射 pass |
| 侧缘环绕系数 0.22 | 太强会让侧面像透光的灯罩、破坏镜面；0.22 保留「光在边缘流动」的暗示又不损质感 |
| watchCaseGeometry chunk 较大（~880KB） | Three.js 主体；已按标签页懒加载，首屏不受影响 |
