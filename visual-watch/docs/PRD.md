## 1. 概述

### 1.1 产品定义

**Glyph Watch** 是一款专注「日程提醒」的独立硬件手表，配合手机 App 使用。手表通过**纯粹的视觉元素**（形状、颜色、位置、环形成进度）向用户传达「现在该做什么」以及「接下来是什么」，表盘**不显示任务文字、不推送消息、不做健康监测**。

App 负责日程的创建、编辑、视觉映射配置与设备管理；手表负责在离线条件下稳定、低打扰地呈现当前状态。

### 1.2 产品形态

```
┌──────────────┐         BLE          ┌──────────────┐
│   手机 App    │ ◄──────────────────► │  Glyph Watch │
│  （配置层）    │    日程 + 视觉规则    │  （表达层）   │
└──────────────┘                      └──────────────┘
```

### 1.3 核心价值主张

| 维度 | 价值 |
|------|------|
| 对用户 | 余光即懂，减少「看屏幕 → 读通知 → 决定行动」的认知链 |
| 对场景 | 会议、创作、带娃、冥想等需要低打扰、高节奏感的生活/workflow |
| 对差异 | 不是更智能的手表，而是更安静的计时伴侣 |

### 1.4 设计信条

1. **一屏一事** —— 同一时刻只表达一个主要状态
2. **先认后读** —— 形状与颜色在 3 秒内可识别，不依赖文字
3. **静态优先** —— 图案本身可理解，动画仅作辅助
4. **配置在 App，表达在表盘** —— 复杂交互不发生在手表上
5. **离线可用** —— 断连后至少 48 小时仍可正确提醒

## 2. 问题与机会

### 2.1 用户痛点

| 痛点 | 描述 | 现有方案不足 |
|------|------|-------------|
| 通知过载 | 手机闹钟/日历通知携带大量文字与操作，打断心流 | 智能手表进一步聚合消息，干扰更多 |
| 抽象时间感弱 | 「14:30 开会」不如「现在该从专注切换到协作」直观 | 传统表盘只显示时刻，不表达「该做什么」 |
| 设备功能冗余 | 用户为「提醒」购买全功能智能手表，却用到 5% 功能 | 价格高、续航短、学习成本高 |
| 视觉语言不统一 | 不同 App 的通知样式各异，无法形成个人节奏系统 | 缺乏可自定义、可内化的符号体系 |

### 2.2 市场机会

- **专注经济与时间管理**持续增长，用户愿意为「减少干扰」付费
- **极简硬件**（Teenage Engineering、Nothing、各种 e-ink 小物）验证了「单功能美学硬件」需求
- 现有日程 App 强在编辑，弱在** ambient 表达** —— 中间层空白
- e-ink / 低功耗 MCU 成熟，小团队可做出可用 POC

### 2.3 产品假设（待验证）

1. 用户愿意为「只看符号就能懂」建立 3–7 天的学习曲线
2. 纯视觉提醒足以覆盖 80% 的日常日程场景（工作块、运动、休息、用餐）
3. 用户可接受手表不显示具体任务名称，详情回 App 查看
4. 7 天以上续航是购买决策关键因素之一

## 3. 产品愿景与目标

### 3.1 愿景

让「知道自己此刻该做什么」成为一种**看的懂、听得少、摸一下就好**的日常节奏，而不是另一块会震、会响、会分心的屏幕。

### 3.2 产品目标（12 个月）

| 目标 | 描述 | 优先级 |
|------|------|--------|
| G1 | 完成 MVP 闭环：App 编辑 → 同步 → 表盘正确表达 | P0 |
| G2 | 10 人内测中 ≥70% 连续使用 14 天 | P0 |
| G3 | 视觉语法可被新用户 3 秒内理解当前状态（可用性测试） | P0 |
| G4 | 典型使用续航 ≥7 天 | P0 |
| G5 | 建立可扩展的视觉映射系统，支持 ≥8 种任务类别 | P1 |

### 3.3 非目标（MVP 明确不做）

- 健康监测（心率、血氧、睡眠）
- 消息 / 来电 / 第三方 App 通知
- 支付、NFC、GPS 导航
- 表盘文字显示任务名（MVP 阶段禁止）
- 应用商店 / 第三方表盘生态
- 语音助手

## 5. 用户场景与故事

### 5.1 核心场景

#### 场景 1：早晨看一眼，知道第一块时间属于什么

> Lin 起床，抬腕。表盘中央是一个**实心蓝色大圆** —— 代表「深度工作」。外环显示当前时段已过去 15%。她不需要解锁手机，直接坐下开始工作。

**验收**：抬腕到理解状态 ≤3 秒；无需文字。

#### 场景 2：会议前 15 分钟，表盘开始「预告」

> 11:45，表盘右下角出现一个**半透明小三角**（协作/会议），主圆饱和度略降。Lin 知道该收尾了。

**验收**：Upcoming 状态与 Active 状态可区分；不依赖 push 通知。

#### 场景 3：在 App 里拖拽调整下午安排，表盘预览实时更新

> Lin 把「运动」从 17:00 改到 18:00。App 内表盘预览立即变化；保存后同步到手表。

**验收**：预览与真实表盘一致；同步延迟 ≤5 秒（连接状态下）。

#### 场景 4：断连仍可靠

> Lin 进会议室手机断连。手表按本地缓存继续显示 14:00–15:00 的「协作三角」。

**验收**：离线 48h 内状态正确；恢复连接后自动增量同步。

#### 场景 5：新用户第一次配置

> Mei 下载 App，选择模板「工作日节奏」，App 预置 5 类视觉映射。配对手表后，当天日程即可运行。

**验收**：首次配置到可用 ≤10 分钟；模板一键应用。

## 6. 产品范围

### 6.1 MVP 范围（v1.0）

**包含：**

- 单设备配对与管理
- 日程 CRUD + 重复规则（daily / weekdays / weekly）
- 5 种默认可视形状 + 色相自定义
- 4 种表盘状态（Idle / Upcoming / Active / Transition）
- 24h 外环时间指示
- App 表盘 1:1 预览
- BLE 同步 + 48h 本地缓存
- 抬腕亮屏（或按键亮屏，取决于硬件）
- iOS + Android App
- 中文 + 英文 App 界面（手表无文字）

**不包含：**

- 多设备管理
- 云端账号与跨设备同步
- OTA 固件升级
- 振动 / 声音提醒（v1.1 考虑可选 haptic）
- 日历订阅（Google/Apple Calendar 导入）

### 6.2 v1.1 候选

- 可选 gentle haptic（仅 Transition 时刻）
- Google / Apple 日历只读导入
- 8 形状 + pattern 变体（ring / dot / stripe）
- OTA 固件
- 多设备支持

### 6.3 v2.0 候选

- 云端账号、家庭共享
- 社区视觉包 marketplace
- 开放 API
- 圆形 e-ink 定制外观版本

## 7. 视觉语言系统

### 7.1 设计原则

| 原则 | 说明 |
|------|------|
| 可学习 | 默认映射符合直觉，7 天内形成肌肉记忆 |
| 可扩展 | 形状 / 色 / 图案三维组合，避免过早耗尽 |
| 静态可解码 | 截图状态下仍可识别，不依赖动画 |
| 色弱友好 | 形状始终是主维度，颜色是辅维度 |
| 低信息密度 | 单屏主元素 ≤2 个（当前 + 预告） |

### 7.2 形状语义（默认映射）

| 形状 | 默认语义 | 说明 |
|------|----------|------|
| ● 圆 | 专注 / 深度工作 | 完整、内聚 |
| ▲ 三角 | 协作 / 会议 / 沟通 | 指向外、交互 |
| ■ 方 | 休息 / 冥想 / 放空 | 稳定、停止 |
| ⬡ 六边 | 社交 / 外出 / 生活 | 多元、开放 |
| ◆ 菱形 | 运动 / 身体激活 | 锐利、能量 |
| ○ 空心圆 | 弹性 / 缓冲 / 未安排 | 可选、低优先级 |

用户可在 App 中修改映射，但系统建议保持形状数 ≤6 以降低认知负担。

### 7.3 颜色维度

- **色相（Hue）**：区分同类下的子类型（如两种「专注」：写作蓝、编码紫）
- **饱和度（Saturation）**：表达紧迫度 / 状态
  - Active：100%
  - Upcoming：60% + 预告角标
  - Transition：交叉渐变
  - Idle：15% 灰阶背景环

色弱模式：自动增强形状描边对比，不依赖红绿区分。

### 7.4 时间环（24h Ring）

- 外环细线，标记 24 小时
- 当前时间指针：小圆点或径向线
- 当前任务时段：对应扇形高亮（同任务色相，30% 透明度）
- 不显示数字时刻（MVP）

### 7.5 表盘状态定义

```
                    ┌─────────────┐
                    │    Idle     │  无当前任务
                    └──────┬──────┘
                           │ 下一任务 ≤15min
                    ┌──────▼──────┐
                    │  Upcoming   │  主形 + 角标预告
                    └──────┬──────┘
                           │ start ≤ now < end
                    ┌──────▼──────┐
                    │   Active    │  主形满饱和居中
                    └──────┬──────┘
                           │ end - now ≤5min
                    ┌──────▼──────┐
                    │ Transition  │  当前渐隐 + 下一渐显
                    └──────┬──────┘
                           │ end 到达
                           └──► Idle 或 Upcoming
```

| 状态 | 进入条件 | 视觉表现 |
|------|----------|----------|
| Idle | 无匹配任务 | 空环 + 弱时间指针 |
| Upcoming | 距下一任务 ≤15min | 主形 60% + 右下角下一形 30% |
| Active | 处于任务时段内 | 主形 100% 居中，环扇形高亮 |
| Transition | 任务结束前 5min | 主形 70% + 下一形 50% 叠化 |

阈值可在 App 高级设置中调整（±5min），v1.0 可固定。

### 7.6 动画规范（辅助，非必须）

| 动画 | 场景 | 规格 |
|------|------|------|
| 呼吸脉动 | Upcoming 最后 3min | 1 周期 / 4s，透明度 ±10% |
| 交叉淡入 | Transition | 800ms ease-in-out |
| 亮屏 | 抬腕 | 300ms 淡入 |

e-ink 版本：用全刷 / 局刷代替连续动画；脉动改为边框粗细交替。

### 7.7 禁忌

- ❌ 表盘显示任务标题、地点、人名
- ❌ 一次显示 3 个以上任务
- ❌ 使用 emoji 或细线图标（小屏不可辨）
- ❌ 强闪烁、高频动画（干扰 + 费电）

## 8. 功能需求

### 8.1 功能总览

| 模块 | 功能 | MVP | 说明 |
|------|------|-----|------|
| 日程 | 创建 / 编辑 / 删除 | ✅ | 含起止时间 |
| 日程 | 重复规则 | ✅ | daily / weekdays / weekly |
| 日程 | 拖拽调整 | ✅ | App 内时间线 |
| 视觉 | 形状 + 色配置 | ✅ | 5 形状 |
| 视觉 | 模板库 | ✅ | ≥3 套预设 |
| 预览 | 表盘实时预览 | ✅ | 与固件渲染一致 |
| 设备 | BLE 配对 | ✅ | 单设备 |
| 设备 | 同步 | ✅ | 全量 + 增量 |
| 设备 | 电量显示 | ✅ | App 内 |
| 设备 | 抬腕亮屏 | ✅ | 或按键 |
| 表盘 | 四态状态机 | ✅ | 见 7.5 |
| 表盘 | 短按预览下一项 | ✅ | P1 |
| 账号 | 云同步 | ❌ | v1.1+ |
| 导入 | 系统日历 | ❌ | v1.1 |

### 8.2 日程管理（App）

#### FR-01 创建日程块

- **输入**：标题（仅 App）、开始时间、结束时间、视觉映射、重复规则
- **约束**：结束 > 开始；最短 15min；最长 12h；同时间不允许重叠（MVP）
- **默认**：新建块继承上一块的视觉或系统默认「圆·专注蓝」

#### FR-02 编辑 / 删除

- 编辑后若影响当前或未来 48h，标记待同步
- 删除需确认；重复任务可选「仅此一次 / 全部」

#### FR-03 重复规则

| 类型 | 行为 |
|------|------|
| 不重复 | 单次 |
| 每天 | 同时间每日生成实例 |
| 工作日 | 周一至周五 |
| 每周 | 同星期几 |

展开逻辑：App 展开未来 7 天实例推送手表；手表缓存 48h，App 负责滚动窗口。

#### FR-04 时间线视图

- 日视图为主；24h 纵向时间轴
- 块上显示文字标题 + 形状色块
- 支持拖拽改时间、捏合改时长（可选 v1.0 仅拖拽起止）

### 8.3 视觉映射（App）

#### FR-05 类别管理

- 预置 5 类：专注、协作、休息、运动、生活
- 每类绑定：shape + hue + 可选 pattern（MVP 仅 solid）
- 用户可新增类别（最多 8 个）

#### FR-06 模板

| 模板名 | 描述 |
|--------|------|
| 深度工作日 | 9–12 专注 / 13–14 休息 / 14–17 专注 / 17–18 运动 |
| 平衡日 | 工作与生活均匀分布 |
| 家长节奏 | 育儿块 + 短工作窗口 |

一键应用模板 → 生成当日 / 重复日程草稿，用户可再编辑。

### 8.4 表盘预览（App）

#### FR-07 1:1 预览

- 渲染引擎与固件共享同一套 `VisualSpec` → `RenderTree` 逻辑（见 15.2）
- 支持时间 scrubber：滑动查看任意时刻表盘状态
- 显示当前状态名（Idle 等）供调试，**该文字不出现在手表**

### 8.5 设备管理（App）

#### FR-08 配对

- BLE 广播名：`Glyph-XXXX`（后四位设备 ID）
- 配对流程：扫描 → 选择 → 6 位 PIN 确认（防误连）→ 绑定
- 单 App 实例绑定单手表（MVP）

#### FR-09 同步

| 类型 | 触发 | 内容 |
|------|------|------|
| 全量 | 首次配对 / 手动 | 未来 7 天实例 + 视觉映射 |
| 增量 | 编辑保存 / 定时 | 变更 diff |
| 心跳 | 每 15min（连接时） | 时间校准 + 电量 |

同步失败：App 显示「上次同步 HH:mm」+ 重试按钮；手表继续用本地数据。

#### FR-10 设备信息

- 电量 %、固件版本、序列号、上次同步时间
- 恢复出厂（清除绑定 + 本地日程）

### 8.6 手表交互（硬件）

#### FR-11 亮屏

- 抬腕亮屏（加速度计）或侧键短按
- 亮屏持续 10s，可配置 5/10/15s
- 无触控屏（MVP）

#### FR-12 按键

| 操作 | 行为 |
|------|------|
| 短按 | 切换「当前态 / 下一项预览」hold 3s 回当前 |
| 长按 3s | 进入配对模式（LED 闪烁提示） |
| 长按 10s | 恢复出厂（需二次确认：连按 3 次） |

## 11. 固件需求

### 11.1 模块划分

```
┌─────────────────────────────────────┐
│           Render Engine             │  形状/色/环/状态 → 帧缓冲
├─────────────────────────────────────┤
│           State Machine             │  Idle/Upcoming/Active/Transition
├─────────────────────────────────────┤
│  Schedule Store  │  Visual Spec     │  本地 JSON/MessagePack
├─────────────────────────────────────┤
│  BLE Stack       │  Power Manager   │
├─────────────────────────────────────┤
│  HAL: Display / Acc / Button / Batt │
└─────────────────────────────────────┘
```

### 11.2 核心逻辑

#### FW-01 时间源

- 首次同步从 App 写入 UTC + 时区 offset
- 本地 RTC 漂移：每天同步校准；漂移 ≤2min/天可接受
- 无同步时用本地时钟继续运行

#### FW-02 状态机

- 每分钟（或事件驱动）评估当前状态
- Transition / Upcoming 阈值可配置（存 NVS）

#### FW-03 渲染

- 双缓冲帧缓冲
- e-ink：全刷 ≤2s，局刷 ≤800ms
- 状态变更时才刷新，静态不重复刷

#### FW-04 存储

- NVS 存：绑定密钥、视觉映射、48h 日程实例、用户设置
- 最大 200 条实例（超出 LRU 删最旧未来块）

#### FW-05 BLE 服务

| Service | UUID (示例) | 说明 |
|---------|-------------|------|
| Device Info | 0x180A | 标准 |
| Glyph Sync | 自定义 | 日程/映射/时间/电量 |

特征值：SyncSchedule, SyncVisual, SyncTime, BatteryLevel, DeviceStatus

#### FW-06 安全

- 配对后 BLE 连接需加密
- 未绑定设备拒绝写入
- 无 PII 存手表

## 13. 数据模型与同步协议

### 13.1 核心实体

```typescript
/** 视觉映射 */
interface VisualProfile {
  id: string
  name: string           // App 内显示，如「深度专注」
  shape: 'circle' | 'triangle' | 'square' | 'hexagon' | 'diamond' | 'ring'
  hue: number            // 0-360
  pattern: 'solid'       // MVP 仅 solid
}

/** 日程块（App 侧） */
interface ScheduleBlock {
  id: string
  title: string          // 不下发手表
  visualProfileId: string
  startAt: string        // ISO 8601
  endAt: string
  recurrence: RecurrenceRule | null
}

/** 展开后的实例（同步到手表） */
interface ScheduleInstance {
  id: string
  visualProfileId: string
  startAtUnix: number    // UTC unix
  endAtUnix: number
}

/** 同步包 */
interface SyncPayload {
  version: 1
  timezoneOffsetMin: number
  visualProfiles: VisualProfile[]
  instances: ScheduleInstance[]  // 未来 48-168h
  settings: DeviceSettings
}
```

### 13.2 手表侧存储限制

| 项 | 上限 |
|----|------|
| VisualProfile | 8 |
| ScheduleInstance | 200 |
| SyncPayload 大小 | ≤32KB |

### 13.3 冲突策略

- **MVP**：App 为唯一信源；手表只读
- 编辑总是 App → Watch 单向推送
- v1.1 若双向：LWW（last write wins）+ 版本号

- GDPR / PIPL 友好：无 PII 上云（MVP）
