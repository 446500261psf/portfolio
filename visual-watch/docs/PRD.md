## 1. 概述

### 1.1 产品定义

**Cove Watch** 是一款佩戴在腕上的**舒适区表达设备**，配合手机 App 使用。

它的表盘不是信息_dashboard_，而是一块**接近椭圆的鹅软石界面**——大圆角、2.5D 微立体边缘、潭状凹面。表盘内**没有文字、没有几何图标**；取而代之的是**持续演化的色彩场与粒子流**，表达此刻与即将进入的**身体—心理舒适区**。

App 负责：日程编排、舒适区映射、轨迹预览与设备同步。  
手表负责：在离线条件下，以 **30fps 动态场**（低功耗时 1fps ambient）稳定呈现当前生命节律。

> v1.0 PRD 中的「几何形状 = 任务类型」方案已废弃。v2.0 以**动态场 + 舒适区坐标**为唯一表达范式。

### 1.2 产品形态

```
┌──────────────────┐         BLE          ┌──────────────────────┐
│    手机 App       │ ◄──────────────────► │     Cove Watch       │
│  · 日程轨迹       │   ComfortProfile +   │  · 鹅软石 2.5D 表体   │
│  · 舒适区编辑     │   ScheduleInstances  │  · 动态场渲染引擎     │
│  · 潭面 1:1 预览  │                      │  · CZM 轨迹插值       │
└──────────────────┘                      └──────────────────────┘
```

### 1.3 核心价值主张

| 维度 | 价值 |
|------|------|
| **具身直觉** | 不用「读」，用「感受」——色温、流速、密度对齐身体状态 |
| **低神经负荷** | 相对 push 通知，动态场不触发文字解码链，减少皮质醇式打断 |
| **节律而非时刻** | 表达「该从深潭进入暖流」，而非「14:30 会议」 |
| **物件性** | 鹅软石形态本身传递安全、温润；科技隐于潭中 |

### 1.4 设计信条

1. **形态先于像素** —— 鹅软石 2.5D 是整个 HCI 的物理前提
2. **场而非符号** —— 禁止用多边形/图标指代状态；只用连续动态
3. **轨迹而非点** —— 日程是在舒适区流形上的曲线，切换是 morph 不是跳转
4. **身体对齐** —— 视觉参数映射激活度/开放度，而非抽象优先级
5. **潭边有岸** —— 内容永不贴边；2.5D 边缘是语义的一部分
6. **配置在 App，浸没在表盘** —— 复杂编辑不上手
7. **离线仍流动** —— 断连 48h 内场态仍正确插值

## 2. 问题与机会

### 2.1 用户痛点

| 痛点 | 深层原因 | 现有方案不足 |
|------|----------|-------------|
| 通知打断心流 | 文字激活前额叶语言回路 | 手表 push 仍是「读 → 判 → 做」 |
| 日历只有「事件」没有「状态」 | 工具理性忽视身体准备度 | Google Cal 不会告诉你「该从静转动了」 |
| 智能手表功能过载 | 通用计算平台范式 | 续航差、视觉噪点多、无物件感 |
| 冥想/专注 App 只有手机端 | 缺乏 ambient 身体锚点 | 开 App = 又一次屏幕依赖 |
| 时间块工具认知成本高 | 符号/色块需学习 | 缺乏与身体感受的直接映射 |

### 2.2 市场机会

- **神经多样性友好设计** rising：非文字、低感官负荷界面有明确受众
- **Somatic / 身心技术** 进入主流（呼吸、Grounding、NSDR）
- **高端极简硬件** 验证了「单意图设备」付费意愿
- **实时粒子/生成艺术** 在 GPU 下放至 MCU 级设备，技术窗口已开
- **2.5D 微曲玻璃** 供应链成熟，可做出差异化形态

### 2.3 产品假设（待验证）

1. 用户能在 **3 秒内** 感受场态方向（更静 / 更动 / 更外向），无需培训
2. **2–3 天** 可建立个人色温-运动联想，优于 7 天符号学习
3. 动态场在 **Approach/Crossing** 时相的提醒效力 ≈ 传统提前 15min 通知
4. 用户接受表盘**永不显示任务名**；详情回 App
5. 鹅软石形态产生**情感依恋**（object attachment），提升 14 日留存
6. AMOLED + 30fps 场渲染下续航 **≥4 天** 为可接受下限

## 3. 产品愿景与目标

### 3.1 愿景

让「知道自己此刻该以何种身心状态存在」成为腕上一块**温润鹅软石**中的自然现象——像看水、看火、看云，而不是看通知。

### 3.2 产品目标（12 个月）

| 目标 | 描述 | 优先级 |
|------|------|--------|
| G1 | App → 同步 → 潭面动态场闭环 | P0 |
| G2 | 10 人内测 ≥65% 连续使用 14 天 | P0 |
| G3 | 3 秒感受测试：A 轴方向判断 ≥78% | P0 |
| G4 | 六原型场互认率 ≥75% | P0 |
| G5 | 典型续航 ≥4 天（AMOLED 30fps 混合策略） | P0 |
| G6 | 鹅软石手板「形态满意度」≥4.2/5 | P1 |
| G7 | 完整 Comfort Field 规格量产化 | P1 |

### 3.3 非目标（MVP 明确不做）

- 心率/HRV **驱动**场态（v2 可选输入；MVP 不做闭环）
- 消息、来电、第三方通知
- 表盘文字、数字时钟、几何 icon
- 应用商店 / 第三方表盘
- 云账号（MVP 本地优先）
- 语音助手

## 5. 用户场景与故事

### 5.1 核心场景

#### 场景 1：晨起，潭面是「静岸」

> Lin 抬腕。超椭圆潭内，30 粒暗绿粒子几乎静止，全屏以 5bpm **呼吸式**明灭。她感到「还可以再慢一会儿」，或自然起身。

**验收**：Dwelling 态场稳定；无文字；3s 内被试描述含「静/慢/休息」语义 ≥80%。

#### 场景 2：写作块中，「深潭」层流

> 9:00–12:00 Deep Pool。钴蓝径向色场，粒子缓慢向中心吸纳。Lin 进入心流；表盘无突变 3 小时。

**验收**：S≥0.85 时粒子 coherence ≥0.9；帧率 30fps 功耗在预算内。

#### 场景 3：11:45 Approach——场开始变暖

> 距 12:00「暖流（协作午餐）」15min。色相向琥珀漂移 20%；边缘粒子开始**向 2.5D 岸汇聚**。Lin 感到「该收束了」，无需 push。

**验收**：Approach 与 Dwelling 可被余光区分；不依赖通知权限。

#### 场景 4：12:00 Crossing——渡越 8 分钟

> 粒子从 inward drift morph 为 orbit；色场钴蓝→琥珀 **800ms 以上**渐变。身体有时间完成切换。

**验收**：参数突变 ≤500ms 禁止；Crossing 时长 5–15min 可配置。

#### 场景 5：App 拖拽改日程，潭面预览实时 morph

> Lin 把运动块从 17:00 移到 18:00。App 内超椭圆预览器即时显示新轨迹；保存后 BLE 同步。

**验收**：`cove-field` 预览与硬件 snapshot hash 一致。

### 5.2 用户故事（MVP）

| ID | 故事 | 优先级 |
|----|------|--------|

## 7. 人机交互基座：鹅软石 2.5D 形态

> 完整规格见 [COMFORT-FIELD-SYSTEM.md §1](./COMFORT-FIELD-SYSTEM.md#1-人机交互基座鹅软石-25d-界面)

### 7.1 形态即交互

Cove Watch 的 HCI 栈**自底向上**：

```
Layer 0  物理形态    超椭圆鹅软石、大 R 角、雾面中框
Layer 1  2.5D 光学   弧面玻璃、唇边高光、潭状景深
Layer 2  动态场      色 + 粒子 + 流向 + 呼吸
Layer 3  时相        Dwelling / Approach / Crossing / Drift
Layer 4  日程轨迹    CZM 插值曲线
Layer 5  App 配置    仅在 Layer 4–5 操作
```

**任何跳过 Layer 0–1 的 UI 决策均视为缺陷。**

### 7.2 关键尺寸（MVP 手板）

| 参数 | 值 |
|------|-----|
| 外壳超椭圆 | 32 × 37 mm（含唇） |
| 有效显示超椭圆 | 28 × 32 mm |
| 中框厚度 | 10.5 mm |
| 2.5D 玻璃弧高 | 0.6 mm |
| 表耳 | 隐藏式，表带融入鹅软石轮廓 |

### 7.3 亮潭（Wake）

抬腕 → 边缘光 **300ms** 渐入 → 场速 ×1.2 持续 200ms → 归 Dwelling 参数。  
像石子入水，而非手机亮屏。

## 7A. 产品定义第二层：用户需求层

> 本节的“第二层”指**产品定义层**，不是 §7.1 HCI 渲染栈中的 Layer 2。
> 第一层定义设备的物理形态与视觉介质；第二层定义用户为什么需要腕上设备、哪些需求不会因为界面范式改变而消失。
> 本节是 **AI-first 长期方向**，不自动扩大 §6 所定义的 MVP 范围。

### 7A.0 不变的底层需求

AI、传感器和 UI 都是解决方式，不是用户需求。用户“雇用”腕上设备的核心工作是：

> 在不拿手机、不中断当前活动的情况下，及时知道与自己有关的变化，并以最低操作成本决定或执行下一步。

#### 用户需求全景

| 底层需求 | 典型场景 | 频率 | 失败代价 | 当前解决方式 | AI-first 机会 |
|----------|----------|------|----------|--------------|---------------|
| 快速确认当前状态 | 时间、天气、下一日程、倒计时 | 极高 | 低 | 表盘 complication | 一瞥只显示此刻最相关的信息 |
| 不错过重要变化 | 来电、消息、日程、安防 | 极高 | 中高 | 全量通知转发 | 按紧急度、关系与情境过滤 |
| 屏蔽不重要变化 | 会议、专注、睡眠 | 极高 | 中 | 勿扰和 App 开关 | 预测打扰成本，选择输出通道 |
| 外包记忆 | 闹钟、待办、服药、位置提醒 | 高 | 中至极高 | 手动提醒 | 理解自然语言和情境触发 |
| 低摩擦微操作 | 计时、音乐、接听、门锁 | 中高 | 低中 | 小屏按钮/快捷键 | 单一主动作、跨模态确认 |
| 理解个人健康趋势 | 睡眠、心率、恢复、活动 | 每日 | 中高 | 指标和分数矩阵 | 相对个人基线合成可信下一步 |
| 运动即时指导 | 配速、强度、路线、恢复 | 人群相关 | 中高 | 运动 App | 根据目标和身体状态动态指导 |
| 发现异常 | 心律、跌倒、持续异常信号 | 低 | 极高 | 阈值报警 | 先验证信号质量，再解释升级路径 |
| 导航与途中指导 | 步行、骑行、返航 | 中低 | 中高 | 地图和转向卡片 | 预测最佳提示时机和模态 |
| 支付、通行与身份 | 交通、门禁、票证、支付 | 中 | 中高 | NFC/钱包 | 提前准备正确凭证；仍需确定性确认 |
| 紧急求助与安全 | SOS、事故、走失 | 极低 | 极高 | 独立安全流程 | AGI 可辅助情境理解，不替代安全协议 |
| 自我调节与习惯 | 专注、活动、呼吸、休息 | 高 | 中 | 目标环与提醒 | 少评分、多情境化方向建议 |
| 身份与审美 | 工作、社交、长期佩戴 | 持续 | 个体化 | 表盘、材质、品牌 | Pool 成为动态但克制的身份表达 |
| 无障碍与独立生活 | 听障、视障、老年、认知辅助 | 人群相关 | 高 | 辅助功能 | 在视觉、触觉、声音间自适应路由 |

#### 高频、低频与真实价值

| 类型 | 典型需求 | 产品判断 |
|------|----------|----------|
| 高频、累计价值高 | 看时间、下一日程、关键状态 | 必须极快、稳定，不应被 AGI 复杂化 |
| 高频、可能为负价值 | 无关通知、重复提醒、模糊健康分数 | 使用频率高不代表需求强，可能是供给制造 |
| 高频、高价值 | 重要通信过滤、服药/关键提醒 | 强人群依赖，需要可靠性和可解释失败 |
| 中频、中高价值 | 运动、导航、支付、设备控制 | 情境明确时价值高，适合腕上微交互 |
| 低频、极高价值 | SOS、事故、异常健康信号 | 不能用日活衡量，必须走确定性安全流程 |
| 低频、低价值 | 腕上长文、复杂搜索、内容创作 | 通常是机械缩小手机，应转交手机/电脑 |

#### 当前最明显的未满足需求

1. **从更多数据变成可信的下一步**
   用户需要发生了什么、可信度多高、是否值得行动，而不是另一张指标表。

2. **通知成为真正的过滤器**
   按人、紧急度、当前活动、可操作性与打断成本决定是否触腕，而不是按 App 全量转发。

3. **个人基线而不是统一分数**
   回答“相对我的正常状态是否变化”，同时保留必要的人群安全阈值。

4. **可理解的准确性与不确定性**
   运动伪影、佩戴松动、数据缺失和模型升级不能被包装成确定结论。

5. **续航、舒适与连续监测的统一**
   睡眠和安全需要持续佩戴；充电、体积、发热与皮肤舒适不能成为事后问题。

6. **隐私与自主权**
   用户需要知道数据在哪里处理、AI 使用了什么、哪些推断可关闭和撤销。

7. **关键能力在必要时脱离手机**
   通信、求助、导航、支付与身份需要有限独立性，但不能以资费、续航和复杂配置换取。

8. **AI 主动性与不打扰之间的平衡**
   真正难点不是“AI 能不能主动说话”，而是什么时候值得打断、错了如何撤销、用户能否审查依据。

#### 三代产品中保持不变的需求

| 不变需求 | 传统手表 | 当前智能手表 | Cove 多模态 AGI |
|----------|----------|--------------|-----------------|
| 时间定向与秩序感 | 时间、日历、计时 | 日程、提醒、情境信息 | 合成“下一步”和准备时机 |
| 低打扰获取信息 | 一瞥读时 | 通知与摘要 | 只呈现需要行动的变化 |
| 减少遗忘 | 闹钟与佩戴习惯 | 待办、服药、位置提醒 | 从自然语言和情境建立提醒 |
| 理解自身状态 | 主观感受 | 连续指标与趋势 | 多源合成、个人基线、可信建议 |
| 保持联系 | 身份与关系符号 | 通信分流 | 按关系与情境准备回应 |
| 安全和求助 | 可靠工具 | SOS、定位、异常检测 | 风险理解 + 独立确定性安全流程 |
| 交易和通行 | 可信物件 | 支付、票证、门钥匙 | 按情境准备凭证，用户确认执行 |
| 自我调节 | 节奏与仪式 | 目标、反馈、习惯环 | 克制的个性化调节 |
| 身份与审美 | 工艺、传承、风格 | 表盘与品牌 | Pool 动态表达但不过度拟人 |
| 自主和无障碍 | 简单、稳定、长期可用 | 多模态辅助功能 | 情境自适应且始终可控 |

### 7A.1 核心判断：未来手表不是小型 Dashboard

今天的智能手表将身体拆成越来越多的指标、应用、卡片和矩阵：

- 心率、HRV、睡眠阶段、压力、活动量分别占据一个界面
- 用户必须主动打开、阅读、比较并解释数字
- 系统告诉用户“发生了什么”，但把“接下来该怎么做”的合成工作留给用户

Cove 的长期方向不是继续增加 UI，而是把 AI 作为**输入与合成接口**：

```text
身体信号 + 行为信号 + 时间/环境 + 日程目标 + 用户主动表达
                              ↓
                  AI 建立可撤销的情境假设
                              ↓
               合成一个方向、时机与强度建议
                              ↓
          Pool 动态场 / 最小确认 / 手机端解释
```

用户不再频繁输入“打开哪个功能、查看哪个指标”，而是：

1. 表达目标或当前感受
2. 允许系统观察有限的身体与情境信号
3. 接受、忽略或纠正一个合成建议

AI 的价值不是替用户作主，而是将多个弱信号压缩成一个**低负荷、可行动、可纠正**的方向。

### 7A.2 先区分三件事：指令、观测与推断

传感器数据不是用户指令，AI 推断也不是事实。系统必须维护：

| 层 | 定义 | 例子 | 语义权威 |
|----|------|------|----------|
| **目标状态 Target** | 用户希望或日程要求进入的状态 | 14:00 准备协作；保持专注 20 分钟 | 高 |
| **主观状态 Reported** | 用户主动报告的身体/心理体验 | “我现在过载”“我还没准备好” | 最高 |
| **观测状态 Observed** | 传感器直接得到的信号与特征 | 静止；心率高于个人基线；昨夜睡眠窗口缩短 | 中 |
| **推断状态 Inferred** | 模型对观测与上下文的候选解释 | “当前恢复可能低于个人常态” | 低，可撤销 |

规则：

1. `Observed` 不得伪装成 `Reported`
2. `Inferred` 必须携带置信度、证据来源和有效期
3. 用户主动报告与纠正优先于模型推断
4. 传感器可以调整建议的**时机与强度**，不能静默改写用户目标
5. 系统不知道时，必须表现为不知道

例如：

> ✅ “当前心率与活动状态不符合你的静息基线；可能有多种原因。是否降低这次过渡强度？”
> ❌ “你正在焦虑，所以不适合开会。”

### 7A.3 传统手表的一般 Input

传统智能手表仍是一个缩小的应用平台，其输入围绕“找到并操作功能”构建：

| 输入类别 | 用户实际给出的指令/信息 | 典型行为链 | 局限 |
|----------|------------------------|------------|------|
| 触控 | 打开应用、点击卡片、滑动列表、切换设置 | 唤醒 → 找入口 → 导航 → 操作 | 小屏菜单深、视觉密度高 |
| 表冠/旋转表圈 | 滚动、缩放、调数值、确认 | 定位控件 → 精细调整 | 仍依赖屏幕 UI 和模式记忆 |
| 物理按键 | 返回、启动运动、快捷功能、SOS | 按键 → 固定动作 | 可靠但语义带宽低 |
| 语音 | 查询、创建提醒、启动功能 | 说命令 → 意图解析 → 执行 | 公共场合隐私、噪声、确认成本 |
| 手势 | 双捏、翻腕、双击 | 当前上下文 → 执行唯一主动作 | 只能承载确认/拒绝类低带宽语义 |
| 健康传感器 | 用户不主动输入；设备采样生理信号 | 采样 → 指标 → 卡片/提醒 | 指标多但解释负担仍在用户 |
| 手机代理 | 日历、消息、导航、设置 | 手机整合 → 手表显示 | 手表常成为手机通知的延伸 |
| 环境上下文 | 时间、地点、光照、海拔、天气 | 规则匹配 → 情境卡片 | 上下文不等于用户意图 |

传统范式的核心行为模型：

```text
用户知道自己要什么
  → 找到对应 App/指标
  → 发出明确操作
  → 手表执行并展示结果
  → 用户自行综合多个结果
```

### 7A.4 Cove 新概念下的 Input

Cove 的输入应从“功能操作”转为“目标、状态、纠正和授权”。

#### A. 被动观测：系统看见了什么

| 输入 | 可能支持 | 不能直接推出 |
|------|----------|------------|
| 时间、日程阶段 | Dwelling / Approach / Crossing | 用户是否愿意执行日程 |
| 抬腕、佩戴、活动/静止 | 注意窗口、运动伪影、采样策略 | 情绪与动机 |
| 心率/HRV 相对趋势 | 与个人基线的偏离、恢复候选 | 焦虑、压力原因、具体心理状态 |
| 睡眠窗口与规律性 | 调整建议时机与强度 | 睡眠疾病诊断 |
| 皮温相对趋势 | 夜间变化、信号质量辅助 | 核心体温、感染原因 |
| 地点、光照、噪声 | 环境是否适合介入 | 用户的主观感受 |
| 历史接受/纠正记录 | 学习提示频率与表达强度 | 永久人格或心理标签 |

被动输入默认只用于生成**候选建议**，不能替代用户意图确认。

#### B. 主动目标：用户想往哪里去

- “保持深潭 20 分钟”
- “今天降低社交负荷”
- “下一段我需要更动一点”
- “不要跟随这次日程”
- “今天只观察，不建议”

目标输入可以通过按键语音、手机端配置或少量触摸完成。目标优先级高于传感器推断。

#### C. 主观 Check-in：用户现在感觉如何

使用身体语言，而不是医疗标签：

- 静 ↔ 动
- 内收 ↔ 外放
- 稳定 ↔ 松散
- 可承受 ↔ 过载
- 准备好 ↔ 尚未准备好

“过载”是用户报告；“心率高于基线”是设备观测。两者必须分别保存。

#### D. 纠正：AI 哪里判断错了

纠正是个性化最重要的训练信号：

- 不是现在
- 方向对，但太强/太弱
- 我需要更静/更动
- 这不是压力，是运动
- 不要再根据此类日程建议
- 恢复默认

每次纠正必须选择作用域：

| 作用域 | 含义 |
|--------|------|
| 仅本次 | 只改变当前建议 |
| 当前情境 | 对这一类日程/地点/时段生效 |
| 长期偏好 | 更新稳定偏好；必须明确确认 |

一次纠正不得自动泛化为永久规则。

#### E. 授权：AI 可以看什么、做什么

授权必须将“读取数据”和“采取行为”分开：

- 读取健康数据
- 读取日历
- 读取位置/环境
- 使用麦克风
- 在本地学习偏好
- 向手机/云发送最小化摘要
- 自动微调 Pool
- 仅提出建议，不自动调整

允许读取心率，不等于允许推断心理状态；允许提出建议，不等于允许自动改变目标。

#### F. 极小的通用动作词汇

无论按键、手势、触摸还是语音，动作语义应保持一致：

1. 接受/现在开始
2. 保持当前
3. 稍后
4. 跳过
5. 降低/提高强度
6. 记录此刻
7. 为什么（转手机查看证据）
8. 取消

AI-first 不等于 voice-first。语音只是复杂目标的输入通道，不能成为唯一通道。

### 7A.5 从输入到合成建议的行为闭环

```text
采集输入
  ↓
来源标记 + 信号质量 + 新鲜度检查
  ↓
分别建立 Target / Reported / Observed / Inferred
  ↓
生成多个候选建议
  ↓
授权、风险、置信度、打扰预算过滤
  ↓
选择一种行为：
  保持安静 / 微调 Pool / 提示过渡 / 请求一次确认 / 转手机解释
  ↓
用户接受、忽略、拒绝或纠正
  ↓
仅在授权范围内更新偏好
```

“合成型建议”不是展示某个指标，而是回答四个问题：

| 维度 | AI 输出 |
|------|---------|
| **方向 Direction** | 更静、更动、更内收或更外放？ |
| **时机 Timing** | 现在、提前、延后还是不介入？ |
| **强度 Intensity** | Pool 的变化速度、亮度与提示强度多大？ |
| **确定性 Certainty** | 自动做低风险微调、给可忽略建议，还是请求确认？ |

示例：

> 下一日程目标需要更外放；昨夜恢复趋势低于个人基线；当前仍处于持续专注。
> 系统不取消目标，而是提前 10 分钟开始、降低 Pool 变化速度，并提供一次“保持当前”入口。

#### 输出门控

| 条件 | 系统行为 |
|------|----------|
| 高置信 + 低风险 | 轻微调整 Pool，不弹文字 |
| 中置信 + 低风险 | 给出可忽略的环境式建议 |
| 低置信 | 保持确定性日程轨迹或请求一次确认 |
| 输入冲突 | 表达“不匹配”，不宣称知道原因 |
| 信号质量差 | 丢弃该窗口，不生成身体状态推断 |
| 高影响/健康相关 | 转手机解释并要求明确确认 |
| 无可靠输入 | 回退至日程驱动的确定性场 |

### 7A.6 新的关键行为时刻

#### 1. 初次校准

- 用户设定目标、节律与打扰偏好
- 系统说明 Pool 是建议表达，不是心理读心或医疗诊断
- 冷启动优先使用规则和日程，不假装已经了解用户

#### 2. Approach：是否应该开始准备

AI 检查下一目标是否仍有效、当前状态是否匹配、数据是否可靠、今日是否已超过打扰预算。默认以 Pool 渐变介入，不弹通知。

#### 3. Crossing：目标与现实不一致

只提供四个低带宽动作：接受、保持当前、延后、强度不合适。用户不响应只表示“无响应”，不能记录为接受。

#### 4. 明显不匹配

例如日程要求进入跃泉，但设备观察到用户仍处于睡眠候选：

1. 先检查佩戴与信号质量
2. 不推断“懒惰、抗拒或情绪低落”
3. 降低介入强度，必要时请求确认
4. 原因解释放在手机端

#### 5. 用户纠正

当前 Pool 必须立即调整；随后询问纠正作用域。不得使用“你偏离了最佳状态”等羞耻或绩效语言。

#### 6. 断连与缺失

- 使用缓存日程与本地规则
- 区分“无异常”和“没有数据”
- 禁止生成依赖缺失手机上下文的解释
- 主动输入与取消必须始终可用

### 7A.7 支撑新 Input 所需硬件

#### P0：首代 AI 行为闭环必需

| 硬件 | 直接观测/输入 | 支持什么 | 不能推断 |
|------|---------------|----------|----------|
| 低功耗 IMU（加速度计+陀螺仪） | 腕部运动、方向、冲击 | 活动/静止、抬腕、手势、运动伪影 | 具体行为语义、情绪 |
| 绿光 PPG | 脉搏波与信号质量 | 心率、合格静息窗口下的 HRV 趋势 | 压力原因、心理状态、诊断 |
| 佩戴/皮肤接触检测 | 是否稳定接触皮肤 | 数据有效性、离腕停采 | 用户是否清醒、是否本人 |
| 接触式皮温 | 腕部局部温度趋势 | 夜间相对基线、佩戴质量辅助 | 核心体温、感染原因 |
| 实体按键/可按压表冠 | 确认的用户动作 | 接受、取消、保持、按住说话 | 复杂意图 |
| 有限触摸区 | 点击、滑动、长按 | 稍后、跳过、强度调节 | 水下/手套场景可靠输入 |
| 单麦克风 + 低功耗音频 DSP | 按键语音、唤醒词、有限声学事件 | 目标、Check-in、纠正；“是否有人交谈”等非语义特征 | 常开层不得自由转写或推断未表达意图 |
| 线性马达 | 输出确认与提醒 | 不看屏幕也能确认输入已接收 | 不应设计过多难记编码 |
| BLE SoC + 安全单元 + 本地闪存 | 连接、端侧计算、密钥、缓存 | 事件检测、特征提取、离线运行 | 开放式复杂推理 |

#### P1：验证收益后加入

| 硬件 | 新价值 | 加入条件/风险 |
|------|--------|---------------|
| 红光+红外 PPG | 静止条件下 SpO₂ 趋势 | 误差与肤色差异验证；不得作为缺氧诊断 |
| 单导联 ECG | 用户主动接触的短时电信号 | 电极、姿势、认证与医疗监管成本 |
| 气压计 | 海拔、楼层、上下坡上下文 | 天气干扰；不等于运动强度 |
| 环境光 | 昼夜与显示亮度上下文 | 袖口遮挡；不等于眼部光照 |
| 双麦克风 | 主动语音降噪 | 防水、孔位、功耗与隐私提示 |
| 低功耗环境视觉传感器 + ISP/NPU | 人数、姿态、室内外、双手占用等短时情境特征 | 腕部视角、遮挡、发热、续航、旁观者隐私；必须事件触发 |
| 硬件视觉指示与物理遮蔽 | 让用户和旁观者确认视觉是否工作 | 必须不可由应用隐藏；关闭状态需可验证 |

#### P2 / 研究项或不建议首代

| 硬件 | 判断 |
|------|------|
| EDA 皮电 | 只能观测出汗相关电导变化，不能识别焦虑或具体情绪；研究版再评估 |
| 独立 GNSS | 功耗、天线、隐私成本高；首代优先使用手机定位 |
| UWB | 近距协同价值有限，首代不必 |
| 生物阻抗 | 易受姿势、皮肤水分和接触影响，解释风险高 |
| 无创血糖/PPG 血压 | 不进入可交付规划，除非独立临床验证与医疗审批 |

硬件原则：

> 传感器数量不是竞争力。每增加一种传感器，都必须证明它改变了哪个行为决策，而不只是新增一个指标页面。

### 7A.8 端—手机—云 AI 分工

| 层 | 职责 | 禁止 |
|----|------|------|
| **手表端** | 佩戴/信号质量、活动状态、伪影检测、手势、短缓存、离线规则、低风险 Pool 微调 | 开放式医疗问答、疾病/情绪诊断、长期因果分析 |
| **手机端** | 多传感器融合、个人基线、日历上下文、建议候选、安全规则、证据与纠错界面 | 将“相关”写成“原因”；绕过用户授权 |
| **云端（可选）** | 最小化摘要的自然语言表达、审核知识库检索、跨设备同步 | 默认上传连续 PPG/原始运动/环境录音；大模型直接控制高影响动作 |

#### 低功耗采样状态机

```text
Idle
  IMU always-on 低频；PPG 短脉冲；温度低频
  ↓ 运动/睡眠/用户动作候选
Context
  提高 PPG 占空比；短时启用陀螺仪
  ↓ 明确事件
Event
  保存事件前后窗口；先检查信号质量
  ↓ 用户主动开始
Active
  语音/运动/主动测量高采样；有明确结束状态
```

模型应优先使用特征和事件，而不是持续上传原始流。电量低时按顺序降级：云服务 → 高频背景采样 → 非关键建议；实体取消与主动输入永不关闭。

### 7A.9 AI 输出合同

每个合成建议在系统内部必须包含：

```typescript
interface SynthesizedGuidance {
  observation: string[]          // 可验证观测
  signalQuality: number          // 传感器是否可信
  inference: string | null       // 可撤销解释
  inferenceConfidence: number
  direction: 'quieter' | 'active' | 'inward' | 'outward' | 'hold'
  timing: 'now' | 'early' | 'later' | 'silent'
  intensity: number              // 0–1
  evidenceLevel: 'A' | 'B' | 'C'
  validUntil: string
  reversible: true
  fallback: 'schedule'
}
```

禁止用一个“AI 置信度”混合所有不确定性，至少区分：

- **SQ Signal Quality**：输入信号是否可信
- **IC Inference Confidence**：模型对候选解释的校准置信度
- **EG Evidence Grade**：建议依据的外部证据强度

语言模型只负责把已通过安全门控的结构化建议表达得自然；不得修改观测、证据等级或安全分类。

### 7A.10 传统范式 vs Cove 新行为模式

| 维度 | 传统智能手表 | Cove AI-first |
|------|--------------|---------------|
| 核心对象 | App、通知、单项指标 | 目标、状态、过渡 |
| 用户任务 | 找功能、读数据、自己综合 | 表达目标、接受或纠正建议 |
| 主输入 | 触控、菜单、表冠 | 上下文 + 极少量高语义输入 |
| 传感器角色 | 生成更多指标页面 | 提供观测证据与建议强度 |
| AI 角色 | 回答问题、执行命令 | 合成方向、时机、强度与确定性 |
| 输出 | 数字、文字、卡片、矩阵 | Pool 动态场 + 最小确认 |
| 主动性 | 通知驱动 | 受置信度与打扰预算约束 |
| 错误处理 | 报错、重试或忽略 | 弃权、降级、保持安静、请求确认 |
| 个性化 | 设置项与推荐 | 用户纠正驱动、作用域明确的学习 |
| 手机关系 | 手表是手机延伸 | 手机负责解释配置，手表负责低负荷反馈 |
| 成功指标 | 点击率、活跃度、任务完成 | 恰当介入率、纠正率、误打扰率、信任度 |

### 7A.11 用新行为模式重构产品

新产品不再以“有多少健康功能”为骨架，而由五个行为模块构成：

1. **Sense｜观察**
   按功耗状态机采集有限信号；每个信号必须有质量标记。

2. **Understand｜建模**
   分离 Target / Reported / Observed / Inferred；以个人基线发现变化，不把变化包装成原因。

3. **Synthesize｜合成**
   生成方向、时机、强度和确定性；先经过授权、风险与打扰预算门控。

4. **Express｜表达**
   默认通过 Pool 表达；只有需要确认、解释或存在高风险时才出现文字与手机界面。

5. **Correct｜纠正**
   用户可立即接受、保持、延后、拒绝和修正；模型只在明确作用域内学习。

这意味着产品首页不应是指标 Dashboard，而应是：

- 当前 Pool
- 系统为何选择保持安静或开始过渡
- 一个明确的纠正入口
- 手机端可展开的证据与历史

### 7A.12 必须直接面对的风险

1. **AI 不能从身体数据读出心理意图**
   HRV 下降可能来自运动、饮酒、疾病、咖啡因、药物、温度或伪影。禁止输出“你害怕、抗拒、缺乏动力”等未经确认的心理结论。

2. **身体状态不等于用户希望的状态**
   用户疲惫仍可能选择运动。Cove 辅助自主决策，不以传感器覆盖用户意愿。

3. **无复杂 UI 不等于无控制与解释**
   必须保留可靠的取消、纠正、授权与手机端解释。AI 不能成为不可见的控制层。

4. **流畅的语言会放大不确定性**
   大模型能把弱相关信号组织成看似完整的故事；“叙事完整性”是风险，不是证据。

5. **忽略不是接受**
   用户未响应可能是没看到、没理解或不想处理。模型训练必须区分接受、拒绝、忽略和未曝光。

6. **动态场的语义仍需验证**
   “低负荷、无需阅读”是产品假设，不是已证实事实；需验证注意率、方向理解、打扰感和可访问性。

7. **健康建议存在监管边界**
   一旦输出疾病名称、临床阈值、持续报警或治疗方向，产品可能进入医疗器械范围。MVP 保持 general wellness，不做诊断承诺。

8. **AI、持续传感、30fps 与续航直接冲突**
   AI 层必须事件驱动、端侧先筛、手机重算，并保留无 AI 时的确定性日程回退。

### 7A.13 版本边界

| 版本 | 输入与行为能力 |
|------|----------------|
| MVP | 日程、ComfortProfile、时间、IMU 抬腕、侧键、确定性 Pool |
| v1.1 | Body Check-in、保持/延后/强度纠正、可选轻触反馈 |
| v2 | 可选 HRV/睡眠趋势、个人基线、建议强度调整；不推断心理意图 |
| AI 探索版 | 按键语音目标、手机上下文合成、置信度门控、纠正驱动学习 |

MVP 闭环保持：

```text
用户设定目标 → 日程驱动 Pool → 用户保持/纠正 → 手机端调整
```

AI 闭环只有在输入语义、授权、信号质量、纠正和失败降级机制齐备后才能进入产品。

## 7B. 产品定义第三层：多模态 AGI 行为层

> 第二层定义“用户需要什么”；第三层定义设备在具体场景中**如何感知、预测、输出和纠正**。

### 7B.1 产品假设与措辞边界

Cove Watch 被定义为一个腕上的**多模态 AGI 接口**：

- 视觉感知环境与用户可操作状态
- 听觉感知语音指令与声学情境
- 肌肤传感器观察有限的生理代理信号
- IMU、日历、位置、设备状态补充行为上下文
- AGI 将这些输入合成为一个适合当下情境的 output

但“AGI”在 PRD 中是**统一交互接口与长期产品方向**，不是能力保证：

> 本产品中的“AGI”不表示系统具有人类水平的通用智能、意识、完整环境理解能力，或在任意任务上的可靠表现。系统只对 PRD 明确定义、可测试、具备权限边界的行为提供保证。

必须避免：

- “知道你真正的想法”
- “准确识别你的情绪”
- “预见你下一步会做什么”
- “已经替你做出最佳选择”

推荐表达：

- “检测到与会议一致的信号”
- “根据日历和当前活动，估计你可能不方便接听”
- “依据有限，保持默认来电方式”
- “无法可靠判断”

核心原则：

> 感知不等于理解；相关性不等于意图；预测不等于授权；置信度不等于安全。

### 7B.2 多模态感知栈

| 模态 | 硬件/数据 | 默认能力 | 约束 |
|------|-----------|----------|------|
| **视觉** | 低功耗环境相机/视觉传感器、手机或跨设备视觉 | 人数、姿态、室内外、双手占用、屏幕/会议候选等场景特征 | 腕部视角不稳定；不得默认全天录像 |
| **听觉** | 麦克风 + 低功耗音频 DSP | 唤醒词、语音活动、多人交谈、噪声类别、用户主动指令 | 常开层不得自由转写；旁观者隐私 |
| **肌肤** | PPG、佩戴检测、皮温，可选 EDA/ECG | 心率/HRV 趋势、接触质量、温度趋势、主动测量 | 只能观测代理变量，不能读取心理意图 |
| **运动** | 加速度计、陀螺仪、可选气压计/GNSS | 抬腕、活动/静止、步行/跑步、驾驶候选、跌倒候选 | 单一运动模式不能确定场景 |
| **系统上下文** | 日历、联系人、通知、耳机、车载、手机状态 | 时间约束、关系、当前设备通道 | 日历事件不表示用户真实意愿 |
| **历史反馈** | 接受、忽略、拒绝、纠正 | 个体提示时机与偏好 | 不得从一次行为形成永久人格标签 |

#### 事件触发，而不是全天原始采集

```text
超低功耗触发层
  IMU / 接近 / 抬腕 / 触摸 / 按键 / 唤醒词 / 来电事件
  ↓
短时感知层
  临时启用视觉、语义音频或高采样率生理传感
  ↓
端侧特征层
  只输出任务所需特征 + 质量 + 时间戳
  ↓
AGI 行为决策层
  不直接访问无限原始流
```

要求：

1. 每次视觉/听觉启用必须有触发源、用途、最长时长和停止条件
2. 原始图像、音频和高频波形默认只存在于易失环形缓冲区，不写入闪存
3. 若任务只需要“是否有人交谈”，不得保留文本、声纹或可重建语音的 embedding
4. 视觉或语义音频工作时必须有系统级不可隐藏指示
5. 提供硬件级麦克风静音；视觉硬件应有物理遮蔽或同等级可信关闭机制
6. 电量、温升或隐私条件不满足时立即降级至日历、IMU 与用户明确输入

### 7B.3 用户如何给出明确指令

明确指令输入按表达能力与可靠性分层：

| 输入方式 | 适合的指令 | 优点 | 约束 |
|----------|------------|------|------|
| **自然语音** | “昨晚睡得怎么样”“20 分钟后提醒我” | 语义带宽最高 | 公共环境、噪声、隐私；默认按键或明确手势启动 |
| **实体按键/表冠** | 接受、取消、保持、唤醒 AGI | 最可靠，可盲操作 | 语义有限，应跨场景保持一致 |
| **触摸 Pool** | 查看、展开、稍后、调强度 | 直接、可发现 | 湿手、手套、运动中不可靠 |
| **腕部/手指手势** | 接受、静音、跳过 | 双手忙碌时低摩擦 | 只能映射低风险唯一动作 |
| **手机端输入** | 长目标、复杂授权、历史纠正 | 高带宽、适合解释 | 不能成为取消/SOS 的唯一入口 |
| **跨设备上下文** | 从消息、日历、电脑任务继续 | 减少重复输入 | 必须显示来源与新鲜度 |

跨模态动作语义固定为：

```text
接受 / 保持 / 稍后 / 跳过 / 强一点 / 弱一点 / 为什么 / 取消
```

同一手势不得在不同场景随机改变为不同高风险动作。

### 7B.4 Output 路由

AGI 不应总用同一种界面回答。输出模态由紧急度、隐私、长度、注意力、环境与可访问性共同决定：

| Output | 适用场景 | 限制 |
|--------|----------|------|
| **Pool** | 整体状态、低紧急建议、渐进过渡 | 不能表达精确时间、金额、对象或风险 |
| **触觉** | 需要注意但不宜公开内容；方向和确认 | 不能仅靠复杂振型表达高风险语义 |
| **声音** | 用户主动提问、耳机已连接、紧迫且环境允许 | 公共场合默认不朗读私人内容 |
| **腕上文字/数字** | 精确答案、来电人、下一日程、导航、风险 | 保持短小；不用长文解释 |
| **手机/电脑** | 证据、趋势、复杂授权、长回复与恢复 | 手机不可用时不能降低确认等级 |
| **自动本机动作** | 预授权、低风险、可逆，如临时降低提示强度 | 必须说明已做什么并提供即时撤销 |

稳态时“表盘无文字”仍成立；以下场景是明确例外：

- 用户主动询问精确答案
- 来电、消息、导航、计时等需要对象或数字
- 风险、异常、数据不足和确认
- 对外通信、支付、身份、安全行为

### 7B.5 两条行为链

#### A. 明确指令链

```text
用户表达指令
  ↓
解析目标、对象、时间与风险
  ↓
调取必要的多模态证据
  ↓
合成答案：结论 → 质量 → 原因假设 → 一个行动
  ↓
选择 Pool / 触觉 / 声音 / 文字 / 手机
  ↓
执行、确认或消歧
```

#### B. 被动预测链

```text
外部事件或状态变化
  ↓
预测当前情境：会议/驾驶/睡眠/运动/独处/双手占用
  ↓
预测用户需求：立即知道/静默排队/稍后汇总/请求确认
  ↓
计算打扰成本、紧急度、置信度、风险与可逆性
  ↓
保持安静 / Pool / 轻提示 / 主动提醒 / 预授权本机动作
  ↓
用户纠正 → 限定作用域学习
```

被动预测的目标不是“猜用户会做什么”，而是：

> 判断此刻应该以什么方式、什么强度、在什么时间把事件交给用户。

### 7B.6 被动预测决策门

对候选 output \(a\)：

\[
Score(a)=C_{ctx}\times U\times B-C_{interrupt}-C_{error}\times(1-C_{ctx})+R\times V
\]

- \(C_{ctx}\)：情境预测置信度
- \(U\)：事件紧急度
- \(B\)：该 output 的预期收益
- \(C_{interrupt}\)：当前打扰成本
- \(C_{error}\)：误判成本
- \(R\)：可逆性
- \(V\)：可逆动作价值

只有同时满足以下条件才允许执行：

```text
数据质量合格
AND 用户已授权该类行为
AND 情境置信度达到该动作独立阈值
AND 风险不超过允许等级
AND 存在明确回退/撤销
```

#### Output 等级

| 等级 | 行为 | 例子 |
|------|------|------|
| L0 观察 | 不输出，继续采样 | 无法判断是否会议 |
| L1 Pool | 低紧急候选进入环境层 | 普通消息稍后汇总 |
| L2 轻提示 | 单次轻触觉 + 简短信息 | 下一日程接近 |
| L3 主动提醒 | 明显触觉/文字，安全时声音 | 连续来电、错误转向 |
| L4 预授权本机动作 | 低风险、可逆、已授权 | 会议中将普通通知临时转为仅触觉 |
| L5 显式确认 | 对外、高影响或不可逆 | 发消息、共享位置、支付 |

不能使用统一的“80% 置信度即可自动执行”。阈值必须按照动作的基础发生率与误判成本分别设定。

### 7B.7 高频明确指令场景

| 用户指令 | 用户真正需求 | 腕上第一层 output | 主要动作 |
|----------|--------------|-------------------|----------|
| “昨晚睡得怎么样？” | 今天是否受影响、为什么、该做什么 | 一句结论 + 质量 + 最大影响因素 + 一个建议 | 记录感受/查看依据 |
| “我现在状态如何？” | 是否适合继续当前活动 | 当前状态候选 + 影响 + 下一步 | 继续/调节/补充主观感受 |
| “下一件事是什么？” | 减少记忆与决策负担 | 事件名、时间、是否该准备 | 开始准备/导航/延后 |
| “20 分钟后提醒我” | 可靠外包记忆 | 回显解析后的内容与绝对时间 | 确认/修改/取消 |
| “开始跑步/专注” | 立即进入模式并减少干扰 | 模式已开始 + 时间/关键目标 | 暂停/结束/延长 |
| “告诉小王我晚到” | 快速沟通且不发错 | 联系人 + 完整拟发正文 | 发送/修改 |
| “带我去最近地铁站” | 获得恰好足够的下一步 | 方向、距离、道路/出口 | 开始/停止/换路线 |

#### 深入场景 A：查看昨晚睡眠

用户问“昨晚睡得怎么样”，通常不是要看睡眠阶段矩阵，而是问：

1. 今天的状态是否会受影响？
2. 与我平时相比怎样？
3. 哪个因素影响最大？
4. 数据可靠吗？
5. 今天该做什么？

AGI 所需输入：

- 睡眠/清醒窗口、体动、心率、HRV、呼吸、皮温等可用信号
- 佩戴完整性、接触质量、缺失区间
- 个人 14/28 天基线与连续睡眠债
- 晚间运动、饮酒、咖啡因、进食、时区、闹钟与环境变化
- 用户醒来后的主观感受

腕上 output 采用“四段式合成”，而不是 Dashboard：

```text
结论：
  昨晚恢复一般，上午可能更容易疲劳。

质量：
  判断把握较高；整夜佩戴完整。

关键依据/原因假设：
  睡眠比你的 28 天基线少约 50 分钟，后半夜更碎。
  较晚入睡可能是影响因素之一。

一个行动：
  上午避免连续高强度安排；今晚可提前约 30 分钟休息。
```

Pool 可表达整体恢复与连续性，但不能替代以下文字：

- 最终结论
- 数据质量
- “原因只是候选”
- 用户明确询问的睡眠时长/时间
- 健康风险和数据缺失

展开层级：

```text
Pool 总体感受
  → 腕上一句结论 + 一个行动
  → “为什么/和我平时相比/数据可靠吗”
  → 手机端时间线、趋势、原始指标与缺失信息
```

冲突处理：

- 数据正常但用户仍疲惫：以主观报告为高权威输入，记录冲突，不说“你其实睡得很好”
- 时长正常但恢复信号偏低：说明冲突，不能虚构原因
- 佩戴中断：明确缺失时段，输出“无法完整判断”
- 疑似异常：描述观测与升级路径，不诊断疾病

#### 明确指令的确认强度

| 风险 | 场景 | 行为 |
|------|------|------|
| 低风险可撤销 | 查看状态、启动计时 | 直接执行并回显 |
| 中风险 | 建提醒、开始运动、改本地设置 | 执行后提供立即撤销 |
| 对外影响 | 发消息、拨号、共享位置 | 执行前确认对象与内容 |
| 财务/身份/健康安全 | 支付、门禁授权、异常处置 | 专用确定性流程，不由生成模型单独决定 |
| 指令歧义 | 联系人、时间、地点不明确 | 先消歧，禁止猜测执行 |

### 7B.8 高频被动预测场景

| 被动事件 | 需要预测的情境/需求 | 高置信 output | 低置信回退 |
|----------|--------------------|---------------|------------|
| **来电** | 是否会议、驾驶、睡眠、双手占用；关系与紧急度 | 选择触觉/文字/声音通道，提供接听/静音/稍后 | 保持系统默认来电，不自动改变 |
| **消息/通知** | 是否紧急、需不需要立即行动、内容是否隐私 | 合并摘要、延后低优先级、突出需行动事项 | 原通知按系统设置送达 |
| **日程临近** | 当前事件是否仍在进行、是否要出发、是否准备好切换 | 提前渐变 Pool，适时提示准备/导航 | 使用固定日历提醒 |
| **导航转向** | 交通模式、定位质量、是否已感知上次提示 | 触觉预告 + 距离/道路名 | 定位不可靠时不输出方向 |
| **睡眠/勿扰** | 入睡、午睡、夜班、是否醒来 | 按预授权调整亮度和普通提示 | 保持手动勿扰设置 |
| **久坐/疲劳候选** | 真久坐还是驾驶/会议；是否适合起身 | 情境结束后给低强度建议 | 进入 Pool 或不提示 |
| **健康信号异常** | 真实异常还是伪影；是否持续；用户能否响应 | 复测 → 明确文字 → 确定性安全流程 | 信号质量差时弃权 |

#### 深入场景 B：接收到一个电话

来电到达时，AGI 不应只问“接还是不接”，而要预测用户此刻的**可被打扰状态**。

##### 输入

- 来电人、关系、近期联系频率、是否连续来电
- 日历中是否存在会议
- 听觉特征：单人/多人交谈候选、环境噪声
- 视觉特征：人数、会议室/道路候选、双手是否占用
- IMU/位置/车载连接：驾驶、运动、睡眠候选
- 耳机连接、手机是否正在使用
- 用户过去对此人和此类情境的选择

##### 需要预测的隐变量

```text
用户是否方便接听？
当前打扰成本多高？
声音、触觉、文字哪个通道可用？
来电是否可能紧急？
用户需要立即决策，还是稍后处理？
```

##### 多证据预测

不能因“日历里有会议”就断言用户正在开会。会议候选应至少组合：

```text
日历会议
+ 当前静止/室内
+ 多人语音活动
+ 电脑/手机会议 App 状态（如已授权）
+ 历史上该地点/时段的行为
```

驾驶候选同样需要速度、道路匹配、车载连接与姿态等多证据，不能只看位置。

##### Output 策略

| 情境 | Output |
|------|--------|
| 无法判断 | 保持系统默认来电方式；显示联系人 |
| 会议中等置信 | 单次轻触觉；显示联系人 + 接听/静音/稍后 |
| 会议高置信且已授权 | 普通来电改为仅触觉；Pool 留下未处理波纹；提供即时撤销 |
| 驾驶高置信 | 不要求阅读长文字；安全时播报来电人，提供语音“接听/稍后” |
| 睡眠高置信且已授权 | 普通联系人静默进入 Pool；连续来电或紧急联系人按独立规则升级 |
| 双手占用 | 放大唯一主动作；允许低风险手势静音 |
| 连续来电/紧急联系人 | 提高紧急度与触觉强度，但仍不自动接听 |

##### 绝不能仅凭预测执行

- 自动接听、拒接、挂断或屏蔽
- 自动回复“正在开会/睡觉/情绪不佳”
- 开启麦克风、录音、转写或摘要
- 向来电方暴露用户位置、健康或推断情境
- 修改联系人长期优先级

允许的自动化仅限于**本机、低风险、可逆、已预授权**的输出方式调整，例如临时将普通来电改为仅触觉。

##### 纠正与学习

每次预测应提供：

```text
原因：检测到日历会议与多人交谈，因此改为仅触觉。
纠正：我没在开会。
撤销：恢复铃声。
作用域：仅本次 / 此地点 / 此联系人 / 以后同类会议。
```

一次拒接不能推断用户不重视此联系人；一次会议误判不能形成永久“工作状态”标签。

### 7B.9 绝不能仅靠被动预测自动执行

无论模型置信度多高，以下行为必须由用户明确确认或独立的确定性安全协议触发：

1. 接听、拒接、挂断、转接来电或发送消息
2. 替用户承诺时间、接受邀请、取消/改期会议
3. 开启麦克风、摄像头、录音或通话摘要
4. 改变导航目的地或共享实时位置
5. 进行医学诊断、调整药物或宣告“安全/无异常”
6. 仅凭生成式预测呼叫急救、报警或紧急联系人
7. 对外共享健康、位置、音频、图像和日程数据
8. 删除通知、消息、健康记录或用户内容
9. 修改闹钟、紧急联系人和穿透规则
10. 支付、购买、签署、身份确认与法律行为

跌倒检测后的 SOS 倒计时属于独立、明确配置、经过验证的安全协议，不属于 AGI 自主预测。

### 7B.10 预测纠正与持续学习

学习优先级：

```text
用户显式规则
  > 用户本次明确选择
  > 多次稳定重复行为
  > 群体先验
```

每次被动 output 必须能够回答：

- 为什么现在出现？
- 使用了哪些数据？
- 是否已经执行了动作？
- 如何撤销？
- 如何纠正？
- 纠正只影响本次、此情境还是长期？

禁止保存：

- “用户焦虑”
- “用户不愿社交”
- “用户可能撒谎”
- “用户不重视某联系人”

此类敏感情境只能作为短时、可过期、可删除的候选推断，不得写入永久人格档案。

### 7B.11 行为层验收指标

| 指标 | 含义 |
|------|------|
| 恰当介入率 | 用户认为提示时机与模态合适的比例 |
| 误打扰率 | 用户明确表示“不该现在出现”的比例 |
| 预测弃权质量 | 低质量输入下系统能否正确不判断 |
| 纠正后即时生效率 | 用户纠正后当前 output 是否立即变化 |
| 撤销可发现率 | 自动本机动作后用户能否快速发现并撤销 |
| 来源可解释率 | 每个预测能否列出真实主要依据 |
| 高风险越权率 | 对外/健康/财务动作绕过确认的比例，目标必须为 0 |
| 原始数据落盘率 | 默认视觉、音频、高频生理原始流写入持久存储的比例，目标必须为 0 |
| 模态重复打扰率 | 同一事件在多个通道无必要重复提醒的比例 |
| 个体公平性 | 不同肤色、语言、残障、活动方式下的错误率差异 |

第三层成功的标准不是“AGI 主动做了多少事”，而是：

> 它是否在正确时间，以最低充分强度，给出一个可信、可理解、可撤销的 output；不确定时是否愿意保持安静。

## 8. 舒适区动态场系统

> 完整规格见 [COMFORT-FIELD-SYSTEM.md](./COMFORT-FIELD-SYSTEM.md)

### 8.1 CZM 坐标（摘要）

- **A** 激活度（静 ↔ 动）
- **O** 开放度（内收 ↔ 外放）
- **S** 稳定度（自由 ↔ 规律）→ 影响粒子相干

### 8.2 六原型（摘要）

| 原型 | 场景 |
|------|------|
| 深潭 Deep Pool | 深度创造、单人专注 |
| 暖流 Warm Current | 协作、对话、共情 |
| 跃泉 Upwelling | 运动、行走、释放 |
| 静岸 Still Shore | 睡眠、冥想、休息 |
| 紊流 Crossflow | 杂务、通勤、缓冲 |
| 空潭 Open Basin | 无安排、自由 |

### 8.3 表达手段

| 手段 | 用途 |
|------|------|
| 色场 gradient mesh | 情感色温、时段基调 |
| 粒子系统 | 能量、方向、社交密度 |
| Curl noise 流向 | 混沌 vs 秩序 |
| 2.5D rim light | 渡越预警、岸感 |
| Breath envelope | 稳定态下的「活着感」 |

### 8.4 时相（摘要）

| 时相 | 触发 |
|------|------|
| Dwelling | 块内稳态 |
| Approach | 下一块前 15min |
| Crossing | 切换窗 ±5min |
| Drift | 无匹配块 |
