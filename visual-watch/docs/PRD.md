## 1. 概述

### 1.1 产品定义

**Cove Watch** 是一款佩戴在腕上的**舒适区表达设备**，配合手机 App 使用。

它的表盘不是信息_dashboard_，而是一块**接近椭圆的鹅软石界面**——大圆角、2.5D 微立体边缘、潭状凹面。表盘内**没有文字、没有几何图标**；取而代之的是**持续演化的色彩场与粒子流**，表达此刻与即将进入的**身体—心理舒适区**。

App 负责：日程编排、舒适区映射、轨迹预览与设备同步。  
手表负责：在离线条件下，以 **30fps 动态场**（低功耗时 1fps ambient）稳定呈现当前生命节律。

> v1.0 PRD 中的「几何形状 = 任务类型」方案已废弃。v2.0 以**动态场 + 舒适区坐标**为唯一表达范式。

### 1.2 产品形态

```
┌──────────────────┐         BLE          ┌──────────────────────┐
│    手机 App       │ ◄──────────────────► │     Cove Watch       │
│  · 日程轨迹       │   ComfortProfile +   │  · 鹅软石 2.5D 表体   │
│  · 舒适区编辑     │   ScheduleInstances  │  · 动态场渲染引擎     │
│  · 潭面 1:1 预览  │                      │  · CZM 轨迹插值       │
└──────────────────┘                      └──────────────────────┘
```

### 1.3 核心价值主张

| 维度 | 价值 |
|------|------|
| **具身直觉** | 不用「读」，用「感受」——色温、流速、密度对齐身体状态 |
| **低神经负荷** | 相对 push 通知，动态场不触发文字解码链，减少皮质醇式打断 |
| **节律而非时刻** | 表达「该从深潭进入暖流」，而非「14:30 会议」 |
| **物件性** | 鹅软石形态本身传递安全、温润；科技隐于潭中 |

### 1.4 设计信条

1. **形态先于像素** —— 鹅软石 2.5D 是整个 HCI 的物理前提
2. **场而非符号** —— 禁止用多边形/图标指代状态；只用连续动态
3. **轨迹而非点** —— 日程是在舒适区流形上的曲线，切换是 morph 不是跳转
4. **身体对齐** —— 视觉参数映射激活度/开放度，而非抽象优先级
5. **潭边有岸** —— 内容永不贴边；2.5D 边缘是语义的一部分
6. **配置在 App，浸没在表盘** —— 复杂编辑不上手
7. **离线仍流动** —— 断连 48h 内场态仍正确插值

## 2. 问题与机会

### 2.1 用户痛点

| 痛点 | 深层原因 | 现有方案不足 |
|------|----------|-------------|
| 通知打断心流 | 文字激活前额叶语言回路 | 手表 push 仍是「读 → 判 → 做」 |
| 日历只有「事件」没有「状态」 | 工具理性忽视身体准备度 | Google Cal 不会告诉你「该从静转动了」 |
| 智能手表功能过载 | 通用计算平台范式 | 续航差、视觉噪点多、无物件感 |
| 冥想/专注 App 只有手机端 | 缺乏 ambient 身体锚点 | 开 App = 又一次屏幕依赖 |
| 时间块工具认知成本高 | 符号/色块需学习 | 缺乏与身体感受的直接映射 |

### 2.2 市场机会

- **神经多样性友好设计** rising：非文字、低感官负荷界面有明确受众
- **Somatic / 身心技术** 进入主流（呼吸、Grounding、NSDR）
- **高端极简硬件** 验证了「单意图设备」付费意愿
- **实时粒子/生成艺术** 在 GPU 下放至 MCU 级设备，技术窗口已开
- **2.5D 微曲玻璃** 供应链成熟，可做出差异化形态

### 2.3 产品假设（待验证）

1. 用户能在 **3 秒内** 感受场态方向（更静 / 更动 / 更外向），无需培训
2. **2–3 天** 可建立个人色温-运动联想，优于 7 天符号学习
3. 动态场在 **Approach/Crossing** 时相的提醒效力 ≈ 传统提前 15min 通知
4. 用户接受表盘**永不显示任务名**；详情回 App
5. 鹅软石形态产生**情感依恋**（object attachment），提升 14 日留存
6. AMOLED + 30fps 场渲染下续航 **≥4 天** 为可接受下限

## 3. 产品愿景与目标

### 3.1 愿景

让「知道自己此刻该以何种身心状态存在」成为腕上一块**温润鹅软石**中的自然现象——像看水、看火、看云，而不是看通知。

### 3.2 产品目标（12 个月）

| 目标 | 描述 | 优先级 |
|------|------|--------|
| G1 | App → 同步 → 潭面动态场闭环 | P0 |
| G2 | 10 人内测 ≥65% 连续使用 14 天 | P0 |
| G3 | 3 秒感受测试：A 轴方向判断 ≥78% | P0 |
| G4 | 六原型场互认率 ≥75% | P0 |
| G5 | 典型续航 ≥4 天（AMOLED 30fps 混合策略） | P0 |
| G6 | 鹅软石手板「形态满意度」≥4.2/5 | P1 |
| G7 | 完整 Comfort Field 规格量产化 | P1 |

### 3.3 非目标（MVP 明确不做）

- 心率/HRV **驱动**场态（v2 可选输入；MVP 不做闭环）
- 消息、来电、第三方通知
- 表盘文字、数字时钟、几何 icon
- 应用商店 / 第三方表盘
- 云账号（MVP 本地优先）
- 语音助手

## 5. 用户场景与故事

### 5.1 核心场景

#### 场景 1：晨起，潭面是「静岸」

> Lin 抬腕。超椭圆潭内，30 粒暗绿粒子几乎静止，全屏以 5bpm **呼吸式**明灭。她感到「还可以再慢一会儿」，或自然起身。

**验收**：Dwelling 态场稳定；无文字；3s 内被试描述含「静/慢/休息」语义 ≥80%。

#### 场景 2：写作块中，「深潭」层流

> 9:00–12:00 Deep Pool。钴蓝径向色场，粒子缓慢向中心吸纳。Lin 进入心流；表盘无突变 3 小时。

**验收**：S≥0.85 时粒子 coherence ≥0.9；帧率 30fps 功耗在预算内。

#### 场景 3：11:45 Approach——场开始变暖

> 距 12:00「暖流（协作午餐）」15min。色相向琥珀漂移 20%；边缘粒子开始**向 2.5D 岸汇聚**。Lin 感到「该收束了」，无需 push。

**验收**：Approach 与 Dwelling 可被余光区分；不依赖通知权限。

#### 场景 4：12:00 Crossing——渡越 8 分钟

> 粒子从 inward drift morph 为 orbit；色场钴蓝→琥珀 **800ms 以上**渐变。身体有时间完成切换。

**验收**：参数突变 ≤500ms 禁止；Crossing 时长 5–15min 可配置。

#### 场景 5：App 拖拽改日程，潭面预览实时 morph

> Lin 把运动块从 17:00 移到 18:00。App 内超椭圆预览器即时显示新轨迹；保存后 BLE 同步。

**验收**：`cove-field` 预览与硬件 snapshot hash 一致。

## 7. 人机交互基座：鹅软石 2.5D 形态

> 完整规格见 [COMFORT-FIELD-SYSTEM.md §1](./COMFORT-FIELD-SYSTEM.md#1-人机交互基座鹅软石-25d-界面)

### 7.1 形态即交互

Cove Watch 的 HCI 栈**自底向上**：

```
Layer 0  物理形态    超椭圆鹅软石、大 R 角、雾面中框
Layer 1  2.5D 光学   弧面玻璃、唇边高光、潭状景深
Layer 2  动态场      色 + 粒子 + 流向 + 呼吸
Layer 3  时相        Dwelling / Approach / Crossing / Drift
Layer 4  日程轨迹    CZM 插值曲线
Layer 5  App 配置    仅在 Layer 4–5 操作
```

**任何跳过 Layer 0–1 的 UI 决策均视为缺陷。**

### 7.2 关键尺寸（MVP 手板）

| 参数 | 值 |
|------|-----|
| 外壳超椭圆 | 32 × 37 mm（含唇） |
| 有效显示超椭圆 | 28 × 32 mm |
| 中框厚度 | 10.5 mm |
| 2.5D 玻璃弧高 | 0.6 mm |
| 表耳 | 隐藏式，表带融入鹅软石轮廓 |

### 7.3 亮潭（Wake）

抬腕 → 边缘光 **300ms** 渐入 → 场速 ×1.2 持续 200ms → 归 Dwelling 参数。  
像石子入水，而非手机亮屏。

## 8. 舒适区动态场系统

> 完整规格见 [COMFORT-FIELD-SYSTEM.md](./COMFORT-FIELD-SYSTEM.md)

### 8.1 CZM 坐标（摘要）

- **A** 激活度（静 ↔ 动）
- **O** 开放度（内收 ↔ 外放）
- **S** 稳定度（自由 ↔ 规律）→ 影响粒子相干

### 8.2 六原型（摘要）

| 原型 | 场景 |
|------|------|
| 深潭 Deep Pool | 深度创造、单人专注 |
| 暖流 Warm Current | 协作、对话、共情 |
| 跃泉 Upwelling | 运动、行走、释放 |
| 静岸 Still Shore | 睡眠、冥想、休息 |
| 紊流 Crossflow | 杂务、通勤、缓冲 |
| 空潭 Open Basin | 无安排、自由 |

### 8.3 表达手段

| 手段 | 用途 |
|------|------|
| 色场 gradient mesh | 情感色温、时段基调 |
| 粒子系统 | 能量、方向、社交密度 |
| Curl noise 流向 | 混沌 vs 秩序 |
| 2.5D rim light | 渡越预警、岸感 |
| Breath envelope | 稳定态下的「活着感」 |

### 8.4 时相（摘要）

| 时相 | 触发 |
|------|------|
| Dwelling | 块内稳态 |
| Approach | 下一块前 15min |
| Crossing | 切换窗 ±5min |
| Drift | 无匹配块 |

## 11. 硬件需求

### 11.1 形态（P0）

- 超椭圆鹅软石外壳；R角 ≥ 45%
- 2.5D 弧面玻璃；唇边高光可见
- 隐藏表耳；硅胶/尼龙一体表带

### 11.2 显示（P0）

| 参数 | 规格 |
|------|------|
| 类型 | AMOLED（粒子场必需；**e-ink 不适用于 MVP**） |
| 尺寸 | 1.2–1.4" 超椭圆有效区 |
| 分辨率 | ≥390×450 逻辑像素（超椭圆 mask） |
| 色域 | 100% DCI-P3 子集 |
| 刷新 | 30fps 活跃 / 1fps ambient |
| 亮度 | 典型 400 nit；亮潭峰值 600 nit |

### 11.3 计算（P0）

| 组件 | 规格 |
|------|------|
| MCU | ESP32-S3（240MHz dual）或 Nordic nRF5340 |
| 协处理 | 可选：专用 2D 加速 / 更高主频 M33 |
| RAM | ≥512KB SRAM（场引擎 + 双缓冲） |
| Flash | ≥8MB |
| IMU | 6 轴，抬腕 |
| 电池 | 280–350mAh |
| 充电 | 磁吸，Qi 可选 v1.1 |

### 11.4 续航

| 模式 | 目标 |
|------|------|
| 混合（30fps×2h + 1fps×22h/天） | **≥4 天** |
