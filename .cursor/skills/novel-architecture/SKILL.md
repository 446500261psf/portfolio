# Novel Architecture（小说架构）

用于搭建/改写长篇小说的设定圣经与卷纲。默认方法来自对《玄鉴仙族》的构书拆解（旁观视角、代际群像、世界压力机、制度写作、受限好运）。

## 何时使用

- 用户要开新长篇、重建大纲、补群像、写制度/暗线
- 用户提到「学玄鉴」「家族流」「群像」「死亡政策」「世界观压力」
- 需要维护 `writing/bible/` 下的故事档案

## 必读材料

1. `writing/studies/玄鉴仙族-构书法拆解.md` — 方法来源
2. `writing/architectures/README.md` — 多套完整故事架构索引（优先）
3. 选定某套后，读该套目录下的 `story.md` 与 `notes/decisions.md`
4. `writing/bible/` 仅为旧草案存档；新架构默认写到 `writing/architectures/<id>-<书名>/`

## 工作流（严格按序）

### Step A — 六问钉桩

先让用户（或根据已有对话）填齐：

1. **鉴**：旁观/半知情装置是谁？能力边界？
2. **压力机**：世界如何吃底层？
3. **第一代锚点**：读者先爱哪 2–3 人？
4. **揭棋盘之死**：哪场死亡打开上层视野？
5. **制度**：家规/教规/晋升惩罚是什么？何时过时？
6. **好运失灵**：哪次关键失灵最必要？

未齐六问时，不要写细纲章节。

### Step B — 更新圣经（最小集合）

新故事默认建在 `writing/architectures/<编号>-<书名>/`。按需更新，保持短、可执行：

| 文件 | 内容 |
|---|---|
| `story.md` | 一句话、反套路宣言、六问、调性、死亡政策 |
| `timeline.md` | 年表（只记改变世界的事件） |
| `state.md` | 当前卷的资源/势力/信息差快照 |
| `plot/outline.md` | 卷纲（求生→揭棋盘→制度升级→抗命数） |
| `plot/threads.md` | 明线/暗线与交汇点 |
| `notes/decisions.md` | 已定决策与否决项（防反复） |
| `characters/*.md` | 每人：习惯/说话/行事 + 三层洋葱经历 |
| `factions/*.md` | 规则、顾虑、吃什么资源 |
| `systems/*.md` | 力量/法律/经济结算 |

### Step C — 人物经历公式

事件清单 ≠ 人物经历。每人至少写：

1. **三层洋葱**：表层轨迹 → 行为模式 → 未愈伤口/未竟渴望  
2. **四句**：事件 / 冲击（原信→发现）/ 选择（而非）/ 代价  
3. **三段**：塑形期 → 断裂期 → 固化期  
4. **与主线咬合**：开场撕旧伤；结局愈合/恶化/带伤活

群像额外规则：

- 每代/每卷主焦点 ≤ 3 人  
- 用习惯、行事、说话风格区分，避免标签复读  
- 先定死亡政策，再安排退场

### Step D — 「讲道理 → 不讲道理」复盘

每条主线高潮检查：

- 因果可追溯？  
- 结果是否仍允许残酷/无常/半成功？  
- 好运是否曾失灵？  
- 死亡是否留下制度或人心余波？

## 输出风格

- 默认简体中文  
- 先给可执行结构，少空评  
- 改设定时同步写进 `notes/decisions.md`（日期 + 决定 + 原因）  
- 不替用户写成整章正文，除非明确要求；优先纲、卡、场景节拍

## 反模式

- 不要堆百科式设定淹没冲突  
- 不要全能金手指带飞共同体  
- 不要用人海冒充群像  
- 不要每死必壮烈；也不要无余波的虐杀
